# 变更管理

火车发车模型——多分支变更合并成批次一起验证、一起发车：

## 三实体

| 实体 | 粒度 | 说明 |
|------|------|------|
| Change | 分支 | 一个变更诉求 |
| IntegrationBatch | 临时集成分支 | 冲突检测 / 批次测试 / 发车状态机 |
| Release | 版本 | 既有发布实体 |

## 流程

1. 变更进批次 → 自动开临时集成分支（即泳道）
2. 批次触发 CI：branch = 集成分支名
3. 测试通过 → 发车（批次整体晋升）；冲突 / 测试失败 → 状态机标记，惰性终态推进（无后台轮询 goroutine）
