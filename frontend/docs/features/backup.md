# 数据服务备份与恢复

新版「数据服务 → 实例详情」查看备份和恢复操作。平台后台提供跨租户备份查询与受控运维入口。

## 当前支持边界

真实快照与恢复目前支持 **PostgreSQL**，通过 K8s 执行面进行 `pg_dump` / `pg_restore`。不能将数据库目录支持的所有引擎都视作已经支持同等备份能力。

需要可用 K8s 执行面、可定位的源实例与归档存储、相应数据服务权限；生产源还需 `prod:write`。仅登记元数据的记录模式不具备真实恢复证明。

## 创建与检查备份

1. 选择实际环境中的 PostgreSQL 实例创建真实快照。
2. 跟进状态，确认完成并具有归档定位和校验信息。
3. 仅已完成且可恢复的真实快照可以进入恢复流程；失败记录先查看执行错误。

## 恢复到新实例

恢复会按源规格创建受配额约束的新目标，保留源实例；不是覆盖原库。

```bash
curl -X POST -H "Authorization: Bearer <Key>" \
  -H "Content-Type: application/json" -H "Idempotency-Key: <8到128字符的稳定请求键>" \
  -d '{"name":"<新实例名称>"}' \
  http://<平台地址>/api/backups/<备份ID>/restore
```

保存返回的操作 ID。网络失败重试复用同一幂等键与相同参数；相同键配不同参数会冲突。配额不足、归档校验不通过、目标创建或导入失败都不能以“操作已受理”视作完成。

## 恢复后核验

跟进操作终态与目标实例就绪，再读取用户表与业务关键数据。归档 SHA-256 校验与导入后读回提供基础证据；业务仍应核对行数、关键记录与应用查询。恢复成功不会自动完成应用切换，绑定与连接配置应在验证后另行处理。
