# 服务运行与排障

新版「工作负载」→ 选择目标，或从「产品 → 服务运行」进入运行详情。页面包含运行概览、实例、日志、操作记录；经典版仍可从应用工作负载进入。

## 先确认观察对象

检查产品、工作负载、实际环境、泳道，以及观察来源和时间。Kubernetes 直读、外部实例和运行态不可用是不同状态；加载失败不等于没有实例。运维操作按资源实际环境校验权限，不以顶栏当前筛选替代。

## 从实例定位原因

1. 看副本就绪、镜像和实例状态，区分等待、运行、终止，检查容器重启次数。
2. 打开实例查看容器日志；多容器时选对容器。应用刚重启可查看上一次终止日志。
3. 查看实例事件，定位镜像拉取、调度、挂载和探针失败。
4. 转到可观测页下钻同一实体的指标、日志和链路；指标/日志聚合/trace 需要采集后端。容器直读日志与 Loki 查询不是同一个数据源。

## 滚动重启与实例重建

- 滚动重启适用于支持该操作的常驻服务，需要填写原因。
- 重建针对指定实例，携带 Pod UID；实例已变化时拒绝操作，应刷新后重新确认。
- 写操作受能力、角色、生产权限及运行状态限制，以页面返回的可用原因和服务端校验为准。
- 受理后检查「操作记录」与实际实例变化。HTTP 202 只表示受理，不证明实例已替换或发布成功；后续发布也可能使旧操作被替代。

接口重试使用同一 `Idempotency-Key`，不要因等待而反复创建新操作。失败时先读操作原因，再处理底层资源或权限问题。

## 容器终端

管理员需开启 `PAAS_TERMINAL_ENABLED=true`（Helm `workload.terminalEnabled=true`），K8s client、Pod exec RBAC 可用，用户具备 `workload:exec`；生产操作另检查生产权限。

在实例详情选择容器并填写原因后建立终端会话。会话有握手窗口、空闲与总时长限制；过期后重新创建。当前实现要求容器内存在可用 shell，distroless 等镜像可能无法进入，改用日志与事件排查。

## 如何判定恢复

核对新实例 UID、镜像与就绪副本，再验证业务探针或真实请求。操作记录成功、Pod Running 与业务结果正确分别提供不同证据。
