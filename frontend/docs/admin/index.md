# 平台管理

`/admin/` 面向平台运维，用户控制台中的租户管理员与平台管理角色不是同一个权限范围。菜单与 API 按领域权限过滤，跨租户查看不意味着拥有所有写操作权限。

## 开通租户与访问治理

1. 在身份管理创建租户，再创建该租户用户并分配角色。
2. 用户从经典或新版控制台进入，按应用成员与角色权限操作。
3. 对 Key 管理到期、轮换与撤销；轮换后更新调用方，检查旧凭证使用边界。
4. 用户会话可单独撤销，不能把 Key 撤销当作浏览器会话也已撤销。

租户可冻结/解冻；退出前查看 offboarding 检查，确认仍归属租户的用户、凭证与业务资源。不要把删除身份记录理解为跨模块业务资源已经清理。

## 模型与平台凭证

管理供应商预设、模型及通道，配置端点、上游模型与平台级 Secret。目录中存在模型不证明上游凭证和能力可用，应按实际协议调用验证。

Secret 在 API 掩码展示。配置主密钥后加密持久化，未配置主密钥的开发模式存在明文兼容；生产配置见[部署方式](../deploy/)。

## 跨租户资源与运维

后台提供工作负载、数据服务、流水线/运行、配置、AI 资产与执行记录等总览及授权操作。先明确当前租户浏览范围，再检查目标资源实际租户与环境。

异步重启、重建、备份和恢复需跟进操作记录与实际状态。备份能力边界见[PostgreSQL 备份恢复](../features/backup)。

## 诊断与审计

通过诊断页检查数据库、构建/Git/镜像库、观测、知识库和执行域等配置与连接情况。诊断是时间点检查，不能代替持续健康与业务验收；未配置、连接失败和无业务数据分别处理。

审计用于查看操作者、时间、资源和操作结果。访问来源、阶段日志、实例 UID、镜像/digest 等证据需按排障任务关联检查。

## 用量与账单

基础配额与账单按租户管理，模型应用归因需应用级 Key。当前部分金额使用平台模拟单价估算；不能当作供应商真实对账或支付渠道结算证明。模型、Key、周期等分析维度以当前页面和契约实际提供的字段为准。
