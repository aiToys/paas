# 新版研发交付实施任务与交接

日期：2026-10-17。设计真源：[新版研发交付与流水线多视图设计](../specs/2026-10-17-development-delivery-design.md)。诊断依据：[评审与源码证据](../../reviews/2026-10-17-console-next/development-flow-review.md)。

本清单供其他 agent 接手；本轮仅交付文档，未修改业务代码、实际分派 agent、提交或部署。

## 0. 开始前

- [ ] 阅读 AGENTS.md、相关设计和当前代码，检查 branch/dirty tree；保留所有已有修改。
- [ ] 复核评审 F1–F8 是否已被其他 agent 修复，不按旧行号机械覆盖。
- [ ] 明确负责文件，协调共同入口（handler、engine、model、templates、router、共享 API）的修改。
- [ ] 本地演示登录在评审时失败，开始浏览器验收前核实实际前后端版本与会话；不绕过登录与权限。

## A. 契约与交付正确性（优先）

建议责任：后端 agent。范围：`internal/devops/pipeline/*`、必要的 devops 数据模型与 adapter、追加 PG migrations、route registry。

- [ ] 定义真实目标、定义快照、候选产物、质量结果、决策、能力 DTO，先与前端对齐字段。
- [ ] 实现只读执行计划 preview 与 planHash 校验，关键变化 409；新增输入仍受现有权限检查。
- [ ] CD 显式选择候选；AI 同次交付取前序构建产物。审批前持久冻结服务/repo/commit/image/digest/build 身份。
- [ ] 消除生产后续 stage 再动态选择 latestReady；旧无快照运行读兼容、写严格复核并重新确认。
- [ ] 原运行重试复用锁定产物；更换候选走新运行/新审批，重复提交幂等。
- [ ] manual test/上线审批/canary 决策记录与权限分开；保留通用 approve 对 canary 的拒绝。
- [ ] 结构化理由、真实事件与检查结果；探活路径回退改为明确策略和记录，不把根路径可达冒充指定检查通过。
- [ ] memory/PG 对齐、追加 migration、OpenAPI 与生成类型；不将领域逻辑搬入 Core。

验收：等待审批时产生新镜像仍发布原 digest；同产品双服务不串镜像；模板升级不改变旧 run；重复请求不重复执行；非成员/无生产权限/过期快照拒绝；数据库恢复后身份和决策不丢。

## B. 恢复新版流程缺口（先复用既有接口）

建议责任：前端流程 agent。范围：`DeliveryChanges.vue`、`ChangeDetail.vue`、`BatchDetail.vue`、`DeliveryPipelines.vue`、`PipelineDesigner.vue` 及相应 API。

- [ ] 恢复新建变更（已有/新建分支）、人工/Agent 选择、新建批次、入批/移出、冲突项定位。
- [ ] 批次重排只在后端支持时启用；成员改变后重新验证，显示实际合并顺序。
- [ ] 修复“去不存在的创建入口”等引导；空态给准确下一步。
- [ ] 配置器支持 canary 与 agent 等实际阶段类型，补 canary 服务/环境/镜像来源；选择器替代手填 ID。
- [ ] 运行前展示 A 的最终计划；A 未完成前只展示明确可解析字段，关键目标未知不伪装可运行。
- [ ] 智能研发范围按设计的四个里程碑解释，展示真实阶段和生产影响，保留现有入口兼容。

验收：人工变更从新建到集成可达；单服务不强制组批；默认 CD canary 可配置；执行前看清服务/环境/泳道/候选；禁止以提示文字代替实际目标解析。

## C. 单次运行多视图与证据（第一批主界面）

建议责任：前端视图 agent。范围：`RunDetail.vue`、新增运行视图组件/领域适配器、`api/pipeline.ts`、`useStatus.ts`、`BuildDetail.vue`。与 B 协调共享 API 文件。

- [ ] 建立单一 run/stage 展示模型和动作解析，graph/steps 共用，修复 succeeded/aborted 枚举。
- [ ] 默认阶段流程图与可切换步骤列表，URL 保存 view/stage；仍为顺序图，不增加假 DAG。
- [ ] 当前阻塞置顶；manual test/approve/canary 各有正确决策按钮，接现有 canaryDecision。
- [ ] canary 面板展示实际候选/基线、地址与观测；未接通指标显示未知，不生成流量百分比。
- [ ] 阶段结果/日志/输入输出/关联资源，补镜像、发布单、实例事件、Agent 证据等深链。
- [ ] 请求竞态、同路由切 runId、终态停止轮询、流销毁、错误态和权限原因。
- [ ] 消除用 updatedAt 推造历史事件；旧数据只展示已知状态与时间。
- [ ] 构建详情区分读取失败与不存在，保留 SSE 日志和失败重试。

验收：canary 不调用通用 approve；图与表同状态/动作；失败到证据 ≤2 动作；切换 run 不串目标；键盘和窄屏可用；不丢已有完整构建日志。

## D. 交付概览、目录与发布矩阵（第二批）

建议责任：聚合视图 agent；A/B/C 完成并对齐后开始，避免多人同时重写主入口。

- [ ] 按设计收敛产品交付任务分组，完整保留旧 section/query 的映射。
- [ ] 流水线列表展示目标摘要、最近运行和迷你阶段条；运行历史补可理解的名称和筛选。
- [ ] 待办关联实体真实状态，标责任/阻塞/等待时长；已解决项不继续作为待处理。
- [ ] 服务×环境矩阵展示基线的期望/观测 digest、时间、发布单与证据；读取失败与未部署分开。
- [ ] 晋升相同候选产物，回退使用已有能力并生成记录；不在矩阵上直接隐式运行第一条 CD。
- [ ] 耗时视图显示执行与人工等待；没有事件的数据不虚构排队时间。

验收：全局和产品上下文一致；多服务/多环境版本不串；单元格到精确 workload/发布单可达；旧链接有效；所有视图使用相同操作权限与版本身份。

## 依赖与合并点

```text
A 契约/快照 ─────┬─ C 完成计划/决策证据接入 ─┐
                ├─ B 完成运行预览接入 ─────┼─ D 聚合与发布矩阵
B 变更基本操作 ──┤                         │
C 图/步骤及现有决策 ────────────────────────┘
```

B 的既有变更接口和 C 的现有 canary 决策可先修复；A 的契约未完成时不伪造成功能力。可分工但不同时编辑同一主组件，集成负责人协调 shared API/model/router。此任务不要求新增独立微服务、通用工作流平台或第二套 UI 框架。
