## A. 身份、作用域与路由语义

建议责任：后端/SDK agent。范围：lane、dataplane、devops 目标映射、SDK；与现有 pipeline 开发协调 model/engine/adapter。

- [ ] 多层保护 default 基线：拒绝普通实体创建/关闭/回收；对遗留 default 实体制定只读修复，不自动删除。
- [ ] laneRef 与机器 key/displayName 分开，关联 branch/PR/change/batch/run，不再按字符串相等判断身份。
- [ ] env 与 service 稳定引用贯穿发现映射；不靠 Service 名拼接猜测新旧基线和 feature 名称。
- [ ] 区分未覆盖、覆盖不健康、缩 0、源读取失败、已关闭/无权；仅未覆盖默认回退本环境基线。
- [ ] 显式 default 覆盖 SelfLane；基线转发保留原 requested lane，支持下游重入。
- [ ] requested/selected lane、环境、版本、实例、reason、配置版本与 Trace 证据可区分；旧 SDK 协议兼容、歧义拒绝。
- [ ] 关闭/部署使用实际目标关系，不以 run.Branch==lane.Name 限制。

验收：default 任意路径不可回收；两环境同名 lane、长名/清洗碰撞、多产品服务不混；A→B→C→D 部分覆盖与重入成立；故障不假回基线。

## B. 生命周期与可恢复清理

建议责任：后端生命周期 agent。范围：lane handler/repository、laneGC、关联运行/配置，协调 A 的稳定身份与保护。

- [ ] 提供关闭影响预览，显示跨产品范围并校验目标权限；实际环境类型未知严格处理。
- [ ] 关闭与并发部署互斥，拒绝新增工作负载或入口；对待执行/进行中的真实 lane 目标核实。
- [ ] 生命周期与 cleanupState 分开，保存 CloseOperation，逐项记录结果、剩余与失败。
- [ ] 关闭/清理重试幂等、重启可恢复，permanent 失败不依赖普通 TTL 回收。
- [ ] TTL 页面使用后端真实 policy/eligibleAt/活动依据；浏览不 touch；延长保留需明确 API/授权。
- [ ] 普通测试联调与生产 release-validation 的策略一致，修正与实际权限不符的注释和 UI 文案。

验收：部分删除失败不显示“全部回收”；显式命名泳道的运行会阻止关闭；复用基线与共享资源不被删；常驻也能完成失败重试。

## C. 地址读模型与入口绑定

建议责任：治理/入口 agent。范围：governance、Workload Ingress、访问地址聚合与控制器适配；不要另造一套域名业务系统。

- [ ] 统一 AccessEndpoint，带精确 target/source、完整 URL、协议、端口/path、用途与可达范围。
- [ ] 治理 Route 与 Workload.domain 统一所有权和 host/path 冲突检查；跨租户错误脱敏。
- [ ] 自动域名使用稳定作用域标识防同名、截断和跨环境碰撞，保留旧地址与自定义域名。
- [ ] 状态区分保存、投影、DNS、TLS、后端就绪、外部/链路验证；失败不返回假可用地址。
- [ ] 核实实际入口控制器能否 Host→lane 绑定和可信上下文注入；支持前只提供“服务直达预览”。
- [ ] 若实现联调入口，复用现有治理/控制器适配，校验租户/env/lane 与访问权限，浏览器打开无需手加 Header。
- [ ] 地址关闭/撤销后不落默认或新泳道；分享不泄漏 API Key，不透传控制台 cookie。

验收：HTTPS/端口/path 不被前端改写；多 host 正确拆分；内部 FQDN 标明范围；重复路由被拒；地址状态与实际观测一致；域名入口不夸大 SDK/链路覆盖。

## D. 前端泳道与地址体验

建议责任：前端 agent。范围：EnvironmentDetail、LaneDetail、Product/Workloads、统一地址卡与范围选择组件、可观测跳转。与正在改交付/运行页的 agent 协调主入口。

- [ ] 产品内局部泳道范围选择，全部环境分组显示；详情固定实际目标，保留旧 lane URL。
- [ ] 泳道列表由实体+部署并集，空泳道可见；legacy 读取不发 POST，viewer 可读。
- [ ] LaneDetail 依设计提供服务版本/访问入口/链路验证/配置依赖/活动回收分区。
- [ ] 服务级有效版本清单与基线比较；矩阵不把所有空格标回退，来源/就绪/预计路由/实测分别显示。
- [ ] 地址按业务入口/联调入口/服务直达/内部分类，主要地址+其它地址，完整复制、明确 target/scope。
- [ ] 所有可观测链接保留 env/laneRef/key，必要时精确 workload；不能只带 lane 名查询全部环境。
- [ ] 显示保留期限、依据与回收进度，关闭预览含跨产品影响，不以接口 200 显示清理完成。
- [ ] 子资源独立错误，详情失败有重试；请求竞态/同路由切 ID/关闭清理正确；视觉 token、键盘和窄屏复用既有规范。

验收：用户能直接回答“当前哪里、本泳道改了哪些服务、其他复用谁、哪个地址能打开、链路是否真的命中、何时回收”；不需要辨认长 K8s 名或手工加 Header 才能理解页面。

## 顺序与验证

1. A 的基线保护/身份作用域与 B 的清理结果优先，不因界面优化延后。
2. A/C 先给真实读模型，D 可同步完成布局与降级状态；契约未完成时不填假成功数据。
3. C 先完成地址类型和冲突，联调 Host 绑定作为可验证能力逐步开放；不要求首版承诺全部协议。
4. 做源码/单元/fake client/PG、前端测试/构建、浏览器、实际 DNS/TLS/入口/多跳链路五层记录。

测试用例必须包括：基线误创建/误关闭；feature 无覆盖与有覆盖不健康；源故障；显式 default；同名两环境；branch!=lane；经过基线重入；非 SDK 服务；多产品关闭与部分失败；TTL 与常驻；自定义域名/旧域名；route/workload host 冲突；DNS 未生效；TLS 未配置；完整 path 和内部端口。

前端在 `frontend/` 执行 `pnpm --filter @paas/console-user-v2 test:ux`、`lint`、`build`。增量契约登记 OpenAPI、生成类型，migration 追加不重写存量。任何真实创建/清理/发布/权限变更先确认会话授权，不通过删生产/基线来验证保护。

最终汇报完成范围、修改文件、真实证据、待验证项和阻塞恢复条件；不要以动画/截图/单个 HTTP 200 判定泳道整链路正常。
