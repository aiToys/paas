# 专项 05：数据服务能力、运维结果与备份边界

状态：设计交接。对应 DS-01；复用 DataServiceDetail、DataServiceOperations 和 MetricChart。

## 1. 当前判断

数据服务列表/详情已有资源创建、连接、托管/外部接入、伸缩、指标、Pod 诊断、MQ 主题与备份记录。当前备份 UI 已明确“只管理记录、不执行真实快照”，应保留这种说明，不列为完全没有运维界面。

问题是备份后端仍直接返回 completed 和确定性模拟大小；持久化记录不等于真实数据备份。各类引擎、托管与外部接入的可操作能力也不应统一由菜单存在决定。

## 2. 页面结构

保留 `/dataservices` 表格，显示类型/引擎/环境/接入模式/运行状态。详情页：概览、连接与绑定、指标、诊断、操作记录；只有引擎支持且权限允许时出现主题、备份恢复等专项。

```text
订单数据库     PostgreSQL · 托管 · 测试环境           [更多操作]
运行就绪：2/2  数据源：K8s  读取时间：xx
概览 | 连接与绑定 | 指标 | 诊断 | 备份与恢复 | 操作记录
阻塞/提醒：备份仅记录模式，当前没有可用于恢复的快照
──────────────────────────────────────────────────────────
当前版本/存储/副本/使用它的产品     最近操作：升级协调中 → 查看证据
```

外部实例显示“已登记/连接检查结果”，不能因登记成功显示 K8s 就绪；Pod、伸缩、平台升级入口按能力解释为不适用。托管也不是所有引擎都支持相同升级和备份策略。

## 3. 能力与操作

后端按引擎、部署模式、版本与权限返回 capabilities（查看连接/凭证、诊断、伸缩、升级、备份、恢复、主题管理等），前端不硬编码“所有 db 都能恢复”。暂缺能力契约时保守显示已有支持，未知来源不当作可托管。

升级/伸缩预览显示真实环境、当前/目标版本与副本、使用者、预期中断和回退边界；版本兼容不明确时不承诺一键降级。后端受理后产生 operationId，操作记录显示排队/执行/等待资源/成功/失败/未知，附 controller/Job/Pod 证据。沿用已有运行操作展示模式，但数据服务语义由自身领域实现。

连接区按来源区分集群内 DNS、可从当前网络访问的外部地址、凭证引用与接入示例。敏感值默认遮罩，显式查看受权限与审计控制；复制动作明确包含哪些字段，不能不经提示把完整 DSN 密码复制出去。

MQ 主题/消费组标明真实 broker 读取或仅平台元数据管理；没有 broker 证据不声称已在消息系统创建。删除主题预览其不可恢复影响与当前环境，不能仅按顶栏环境决定确认。

## 4. 备份分两阶段

### 阶段 A：校正当前记录语义

立即保留“添加备份记录”名称，列表标“记录模式/无恢复证明”；模拟大小显示“模拟值”或不显示，completed 映射为“记录已创建”，不要改成“备份可恢复”。没有 provider 与产物定位的历史记录不提供恢复按钮，不因迁移补造真实对象存储地址。

这一步可以改善信任，但不算完成灾备能力。前端与 API 响应应有明确 mode/provider/verification 字段；兼容旧记录时从真实后端边界判断，不只对某个 ID 前缀猜测。

### 阶段 B：引擎级真实备份与恢复

首个引擎范围由维护方选择已有适配与环境可验证者，不一次承诺六类引擎。备份分“已受理/运行中/已上传/完整性校验/失败”，记录实例 UID、引擎与版本、范围、时间、一致性类型、存储引用、校验和、保留策略和错误。状态由执行任务与产物证据推动。

恢复默认创建新实例，预览备份兼容性、目标环境、资源需求、网络/凭证、可能的数据丢失范围。覆盖原实例作为独立高影响操作，要求明确备份、目标与停机计划。恢复作业完成仍需引擎健康与数据验证，之后才称“恢复验证通过”；校验和通过也不等于可恢复验证通过。

备份清理区分删平台记录与删真实产物；产物被 retention 删除后标过期不可恢复。凭证使用 SecretRef，不把存储密钥写进操作日志。

## 5. 契约依赖与非目标

新增领域能力、操作记录、backup mode/产物/验证字段，以及对应持久化与引擎执行器；与已有 Workload 操作记录可以共享组件，不直接混用两个资源的权限与完成判据。必须兼容原 `/api/backups`、数据服务与租户隔离。

本专项不承诺跨地域灾备、自动故障切换、通用无损升级、任意历史时间点恢复。只有接入并实测的引擎才展示对应能力。

## 6. 验收

- 记录模式创建后不会显示“可恢复”，模拟大小不能混入真实容量统计；旧记录无 provider 时仍正确标识。
- 同一引擎的托管/外部实例显示不同可用操作；缺授权与不支持各有明确原因，后端仍拒绝越权。
- 升级/伸缩 API 受理但 controller 失败时，页面可查失败证据；重新打开详情仍能追踪 operation。
- 真实备份任务失败、上传失败、校验失败可区分；不把已受理标成功。
- 在隔离测试目标完成“写入验证数据→备份→恢复新实例→读回校验”，记录版本/对象/时间作为恢复证据；未执行该流程不声称灾备完成。
- MQ 和连接信息展示明确数据来源；凭证查看/复制/错误日志不会无意包含其他租户或平台密钥。
