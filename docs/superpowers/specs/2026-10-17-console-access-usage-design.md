# 专项 06：成员、凭证生命周期与用量口径

状态：设计交接。对应 AC-01/02、BL-01 与 UX-01；保留现有租户/应用 RBAC 和管理员边界。

## 1. 当前能力与缺口

成员已有角色、受限模式、添加/修改/移除；Secret 已掩码与审计；API Key 已一次性显示；配额已有专门调整权限和应用 Token 归因。优先修复读取失败被当作空、作用域解释不足、账单支付措辞超过实际实现边界。

本专项不把前端缺少禁用按钮解读成后端没有授权；需要按角色做实际验证。也不把有 PG 持久化视为已具备结算与支付网关。

## 2. 成员与有效权限

产品成员页优先显示成员列表与“当前用户为什么可操作”说明，租户管理员继承权限、应用角色、受限模式含义分开。普通开发者/观察者读到页面时不展示可误点的管理控件；若缺少权限信息则显示需权限，不猜测。

成员列表与可添加用户列表独立请求；403 解释无权查看/管理，503 可重试，真正空列表才显示无成员。读取失败时不据空数组允许删除保护或推断“无人管理”。重复姓名以 userId 为身份，显示名称/邮箱便于区分。

开启受限模式前显示实际影响和当前操作者保留的权限；最后负责人移除、自降权、并发角色修改是否允许由后端领域规则决定。UI 展示预检结果，不能用本地列表推断仍有负责人而绕过后端检查。

## 3. API 密钥

首期保留现有能力与权限继承语义，创建确认明确“与当前账号相同权限”，不生成误导性更窄 scope。创建结果用专用一次性展示区，复制反馈可见；关闭弹层/切页/退出时清空明文 ref，日志与普通列表仅用指纹/掩码。

```text
API 密钥          当前组织：Acme                [创建密钥]
用途/名称 | 指纹 | 权限摘要 | 到期 | 最近使用 | 状态 | 操作
接入说明：环境变量示例（占位） → 最小调用示例 → 排错入口
```

名称、用途、权限范围、到期、最近使用等字段是目标契约；不存在的字段显示未提供或不渲染，不补当前时间/永不过期等假值。

后续最小权限设计：创建时选择可授予的 scopes、应用范围与有效期；有效权限是创建者可授予权限与所选范围的交集。API 请求后端强制校验，浏览器控件不提供超出权限的选项。管理员角色不能简单复制为一把长期全能 Key。

轮换采用“创建替代 Key→部署使用方→查看最近使用/验证→撤销旧 Key”，明确重叠窗口和手工确认；没有使用方遥测时不自动认定迁移完成。撤销展示实际影响与即时失效边界，失败不隐藏旧 Key。

## 4. Secret 与证书

租户/平台作用域常驻标识；平台共享写能力按后端授权呈现。引用关系显示哪些通道/工具/应用使用（只有有契约的引用），删除影响无法获取时写未知，不能按“0 引用”提示安全。

组织级 Secret 删除确认根据真实作用域与已知引用，不根据顶栏是否浏览生产环境决定；有生产引用时提升确认说明，未知引用则明确未知。读取列表不含环境参数的当前实现，不应暗示顶栏切换会改变 Secret 的租户作用域。

创建/替换后关闭与成功清除明文草稿；证书格式/有效期只有后端解析结果才展示。轮换与证书到期通知依赖元数据、更新 API、resolver 刷新与实际消费者机制，不能只加一个前端日期列就宣称自动轮换。

审计按资源、动作、操作者、时间过滤，提供可复制资源 ID 与详情；敏感值、完整 API Key、工具 apiKey 不进入审计正文。若审计接口不可用，资源列表仍能读，审计区单独提示。

## 5. 用量与配额页面重新组织

默认“用量与配额”，包含资源配额、模型调用用量、估算记录三个区。当前 quota/usage 可继续使用，但每项需标单位、统计范围、更新时间、累计/当前值，以及是否参与强制拦截。

模型部署/GPU 等目录中暂不适用的资源不能当作实际租户购买项；只有真实采集数据才展示非零使用。应用 Token 归因保留，但需要解释未归属应用用量与统计覆盖，不把子集之和当作全组织总量。

当前 billing 实现用当前 Counts×固定 PriceTable 生成指定 period 的记录，未按 period 读取期间计量事件；PayBill 更新数据库状态，没有资金支付凭证。因此：

- 价格未接真实套餐时称“示例单价/费用估算”，金额与依据一同展示；不能称正式应付账单。
- period 只作估算记录标签时明确说明，不提供看似真实的历史月费用趋势。
- “支付”改为符合实际能力的“标记处理/模拟结算”并明确不会扣款，或在正式模式隐藏；生产产品不以数据库 paid 字段冒充到账。
- 配额写、估算生成与处理动作仍遵循现有权限；此前管理员可调整配额的能力不是本专项新功能。

不能只在页脚加一个很小的免责声明，主标题、状态、按钮和明细中均需准确命名。旧 paid 记录标来源与处理方式，不能迁移成真实支付流水。

## 6. 真实结算的后续门槛

这是独立后端能力范围，不要求前端 agent 顺手造一个财务系统：

| 能力 | 必须提供的证据 |
|---|---|
| 时段计量 | 事件来源、租户/应用/模型/Key 归因、去重 ID、开始/结束/时区、延迟与补录规则 |
| 单价 | 币种、单位、价格版本、生效区间、免费额度/套餐与舍入规则 |
| 出账 | 固定时段快照、明细可核对、不可变已确认记录与更正机制 |
| 支付 | 实际收款/支付渠道状态及引用、幂等回调、失败状态；离线人工确认也标人工凭证来源 |
| 用量数据质量 | 实测/估算/缺失、更新时间、归因覆盖与未归属部分 |

无对应证据前保持估算/模拟边界，不展示支付成功或精确成本节省结论。浏览用量不依赖物理环境，筛选范围为组织/应用/模型/Key 等实际计量维度。

## 7. 契约与交付拆分

前端可立即完成：成员/Key/Billing 独立错误态，API Key 明文清除、作用域与继承文案，现有模拟账单准确命名。名称/scopes/有效期/使用时间、Secret 引用/更新/轮换、真实时段计量均需后端/API/存储支持后再开放控件。

权限检查共享现有 session permissions 与后端 grants 语义，不另建前端角色映射真源。新字段统一 OpenAPI 生成类型；API Key 明文仍只在创建响应一次返回。

## 8. 验收

- 成员接口 403/503、用户选择器单独失败、真正 0 成员三类呈现不同；角色变更失败保留真实旧角色并提示。
- 同名不同用户可区分；受限模式与管理员继承权限说明准确，直接 API 越权仍由后端拒绝。
- 创建 Key 后关闭/切页/退出均清除明文状态，再次打开不回显；日志与审计不含完整值。
- 顶栏选择测试/生产/全部时，组织 Secret 的作用域和后端授权保持一致，确认解释真实影响。
- 当前估算按当前计数生成时明确口径；选择历史 period 不伪装历史实际用量；“标记处理”不能显示真实扣款成功。
- 用量失败不显示 0、无权限不显示空；精确 Token、估算 Token、输出字符在不同页面保持同一标签语义。
