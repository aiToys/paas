# 专项 01：AI 工作流编排与执行追溯

状态：设计交接；问题 WF-01/02/03，证据见 [检查报告](../../reviews/2026-10-17-console-next/all-modules-audit.md)。

## 1. 现状判断

当前不是缺少执行引擎：已有条件分支、人工确认、节点输出、运行轮询、终态自停、循环与可达性后端校验。应保留这些能力。问题在于编辑动作与真实连线不一致，历史运行依赖当前定义解释，工作流记录不在当前全局 AI 执行页中。

`Workflow.vue` 新增节点未重接前驱，导致用户按常见“添加步骤”思路编辑后被后端拒绝；删除时写死终点 ID。`WorkflowRun` 未持久化定义快照，本进程的定义值副本只保护当前 goroutine；paused 在重启后恢复会读当前定义，不能当作跨进程不可变快照。运行中断被 Sweep 标失败是已有恢复边界，不应对用户承诺自动续跑全部任务。

## 2. 页面结构

保留 `/ai/workflows` 列表，新增详情路由是提案：`/ai/workflows/:id`，内部编排/运行记录两区；运行独立深链建议 `/ai/workflows/:id/runs/:runId`。先实现时可把 runId 放 query 并提供可恢复链接，但必须可刷新/分享且不与 `/ai/:section?` 或外部 `/ai/runs/:name` 混淆。

```text
AI 开发 / 工作流 / 客服分流        草稿变更未保存    [校验] [保存] [试运行]
配置版本及依赖摘要：3 Agent · 1 工具 · 1 等待确认点
────────────────────────────────────────────────────────────
节点目录 200–224px │ 拓扑画布（剩余宽度）     │ 节点配置 320–360px
开始/智能体/工具   │ 开始 → 分类 → 条件分支   │ 名称 / 类型 / 下一步
条件/人工确认/结束 │ 售后 → 人工确认 → 回复   │ 变量选择 / 输入预览
                  │ 咨询 → 回复 → 结束       │ 依赖状态 / 字段错误
────────────────────────────────────────────────────────────
校验结果：2 个错误、1 个提醒 → 点击定位节点或字段
```

小屏隐藏节点目录为“添加节点”按钮，属性切抽屉；画布提供缩放、适应全图、键盘选择。所有连线操作有等价表单方式，不依赖拖拽才能完成任务。列表保留名称、是否启用、配置更新时间、依赖阻塞；最近运行/版本字段在接口具备后展示。

第一阶段不必引入图编辑库：先“真实只读拓扑＋表单选边＋插入按钮”，修复语义；后续图编辑仍以同一 NodeDef 图为真源。

## 3. 编辑行为与验证

1. **在线上插入**：选定 A→B，插入 N 后变为 A→N→B；条件节点必须选具体分支边。没有指定边的“新增节点”只添加待连接节点，明确警告不可达，不伪装已经加入主路径。
2. **删除**：普通单后继节点可预览重接 A→B；条件节点/多入边必须展示影响边，由用户选择重接或撤销。不得统一跳到某个硬编码 end；允许多个 end 的后端语义保留。
3. **改 ID**：内部稳定标识与展示名称分离。若兼容允许编辑现有 ID，前端原子重写所有出入边及模板引用并展示变更，不只改名称字段。
4. **条件**：提供变量/比较符/值控件，显示分支顺序与默认分支。现引擎是按条件选择路径，不代表并行执行；多个条件匹配时的顺序按后端实际算法显示。
5. **变量**：从输入与该节点之前可用输出插入；分支专属输出不能当作必然存在。当前引擎模板为 string、工具 Args 为 map[string]string，变量选择器不得暗中发送任意 JSON；类型化参数属于后续契约升级。
6. **校验**：本地检查结构、重复 ID、悬挂连线、孤立节点、环、必填配置；服务端为权威校验，并返回可定位的 nodeId/field/code。依赖存在/启用/权限/模型协议另列就绪检查，不混入“图合法”。

试运行前保存/确认当前定义，明确运行的是哪个版本。当前“发布”指发布到资源广场，命名改“发布到广场”；没有工作流发布版本契约前，不能新增一个看似已生效的“发布上线”开关。

## 4. 运行工作台

默认展示执行拓扑，选中节点展示输入、输出、错误、耗时；提供实际路径列表视图。未经过的分支标“未执行”，等待确认使用独立状态，不能显示为失败。输出以可展开文本/JSON 呈现，超长按需加载，不把全部输出一次铺满画布。

运行页顶栏始终显示 runId、定义版本/hash、创建者、时间和输入摘要；定义变更后仍显示历史节点名称与图。刷新失败保留上次记录并标过期；404/权限失败/暂时离线分别提示，不无限静默轮询。人工确认展示当时的节点说明、此前结果、执行后继与操作者权限；确认和中止防双击。

“重新运行”创建新 run，保存来源运行链接。暂不提供“从失败节点重试”按钮：外部工具可能有副作用，必须先定义幂等与恢复边界。

## 5. 必要契约

以下为新增设计，不是已存在字段：

| 能力 | 最小契约与约束 |
|---|---|
| 定义快照 | Run 保存 definitionSnapshot 或引用不可变 revision＋hash；NodeRun 以快照解释，paused 恢复同样读取快照 |
| 依赖快照 | 至少记录 Agent/Tool 的引用与配置版本；若暂不能冻结依赖，运行页明确“定义已固定，依赖运行时解析”，不得宣称全链路可复现 |
| 创建运行 | 接收预期定义版本，版本冲突返回 409；输入字段 schema 可先为独立可选元数据，兼容原有 string map |
| 列表与详情 | 只列当前租户可见记录；支持 workflowId/status/time/page 查询；原 API 保持兼容 |
| 历史保留 | 删除定义对历史的影响明确；中期改归档，历史保留遵循租户策略，不能仅改前端文案掩盖现有级联删除 |
| 关联证据 | traceId/requestId 有值才显示；无采集时说明，不生成看似可点击的假链路 |

存量 run 不补造 snapshot；标“历史定义快照不可用”，从当前定义获取的信息只标参考。迁移前的 paused run 需明确处理策略：恢复前校验兼容性或要求中止后重跑，不静默套新定义。

## 6. AI 执行记录聚合

`/ai/runs` 保留旧路径，增加“智能研发任务 / AI 工作流”来源筛选；后续 chat 请求有持久追踪后才加“模型/智能体调用”。当前 Agent 对话不等于外部 agentrun，不默认出现在同一列表。

列表显示来源图标、对象名、实际来源状态、开始/结束、发起者、证据入口。统一展示分类可为进行中/待确认/成功/失败/中止/未知，但保留原状态；取消、审批、重跑按来源能力提供。无需为首期建设跨引擎调度总线，可使用来源 tab 独立分页和错误态。

## 7. 验收场景

- 从 start→end 在线上插入一个 Agent 节点，连线正确，后端校验通过；改名终点再删除中间节点，不出现悬挂 ID。
- 条件分支、多个终点、未连接节点、环、跨分支输出引用分别有可定位说明；图形与表单反映同一配置。
- 运行 A 暂停后修改定义为 B、重启进程、审批 A：使用 A 的持久快照或明确拒绝恢复；不得无提示执行 B。
- 旧运行无 snapshot 有清楚标识；刷新深链仍停留选中 run/节点。
- 外部 agentrun 不可用时，工作流运行列表仍能读取；模型对话未入库时不出现在假“全部运行”列表。
- 键盘可新增、选边、配置、校验并定位错误；窄屏能阅读运行与完成人工确认。
