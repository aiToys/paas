# 专项 02：AI 资产准备、验证与复用

状态：设计交接。覆盖智能体、知识库、工具、提示词、技能、资源广场；依据 AI-01～06。

## 1. 现状与目标

已有资产 CRUD、引用、广场整包复制、MCP 测试、KB 上传检索、Agent 评估与评估历史。这些应保留。缺口是“已创建/已启用”难以说明是否能用于下一步任务，列表读取对辅助依赖过度耦合，安装后配置未形成连续路径。

共同任务：创建/安装 → 补依赖 → 验证 → 试用 → 绑定到 Agent/工作流 → 查看结果。就绪状态由实际检查产生；无法访问依赖时显示未知，不能仅凭 enabled=true 画健康徽标。

## 2. 页面布局

列表统一为名称/关键配置/引用/就绪提示/最近修改/操作，默认 20 条，筛选保留在 URL。主列表请求单独处理，引用统计失败显示“引用情况未知”，不能隐藏资产或据此允许高影响删除。

资产详情首屏结构：名称与来源 → 当前阻塞及修复入口 → 配置摘要 → 使用它的对象 → 试用/验证。长编辑移到独立详情；Prompt/Skill 小编辑可保留自适应抽屉。引用对象以名称链接展示，ID 可复制，避免手填。

```text
知识库 / 产品文档          准备未完成 · 向量库不可用        [验证配置]
对象存储 已连接    向量库 无法连接    嵌入模型 待验证
概览 | 文档与索引 | 检索测试 | 被谁使用
文档列表：名称 / 类型 / 阶段或现有状态 / 切片 / 失败说明 / 操作
```

## 3. 智能体

编辑分为基础（模型、说明）/行为（system Prompt 与模板）/能力（Skill、工具、KB）/执行限制（maxSteps）。不是四层路由，用段落与锚点组织。

显示当前配置优先级：systemPrompt 与 promptRef 同时配置时，解释实际采用来源；Skill 如何叠加以运行时规则为准。保存前预览最终指令来源与资产引用；敏感工具凭证仅显示已配置状态。

依赖检查项包括模型协议/工具调用能力、工具启用与连通、KB 是否存在可用索引、模板是否可解析。先前端展示已知条件，远程验证由后端提供；缺验证能力时标“未检查”。保存草稿不要求所有依赖健康，启用/试运行前展示阻塞。

运行期依赖失败同样需要反馈。当前 buildSystem 会静默跳过失效 Skill 或检索失败的 KB；成功返回文本不能证明组装能力完整。后端增加非敏感的运行 warnings 与实际采用资产清单，区分“执行完成”“依赖降级”；配置可声明哪些依赖必需，必需项失败时明确终止。不能仅在前端预检一次后假定运行期间始终健康。

已有试运行与评估合并到详情“调试与评估”区域，保留用例与历史。结果至少绑定 Agent 配置 hash、模板版本、模型与评估规则；已有 contains/精确等规则明确列为规则匹配，不能宣称是人工验收或完整语义质量评分。生产调用内容不自动复制到评估集。

## 4. 知识库

创建向导为“数据落点 → 嵌入配置 → 文档 → 检索验证”。从真实可用数据服务中选向量库/对象存储，展示环境和连接状态；没有资源提供带返回地址的创建入口。绑定跨环境资源时说明网络与权限边界，不能按顶栏筛选后自动选第一项。

嵌入模型取自能力目录，只列兼容 embedding 的模型；维度从模型/向量集合契约读取或明确手动验证，不能固定 1024 后宣称兼容。配置创建后，变更模型/维度应走新索引重建与切换，不默默覆盖已有向量。

当前只有 parsing/indexed/failed，首期继续准确显示这些状态与 message；若后端提供细阶段，再显示上传/解析/切片/向量化/索引进度，禁止前端模拟百分比。失败展示发生阶段、可重试条件、已保留的数据；没有重试 API 时提供重新上传并说明重复处理策略。

保留检索测试，增强来源文档、页码/片段、索引版本、score 解释与查询参数。score 不是回答正确率。ChunkHit 当前只返回片段/序号，文档跳转和索引版本需要新增契约，不从文本猜来源。

## 5. 工具

按实际能力显示测试：MCP 为“连接与发现”，展示 tools/list 的方法名、说明、input schema；HTTP/builtin 未实现测试时显示说明而非点击后报 400。Agent/workflow 参数选择使用发现结果，有缓存时标发现时间。

当前 Agent 的 buildTools 调用也只支持 MCP，HTTP/builtin 不只是缺少测试。在 Agent/工作流选择器中按真实可调用能力禁选并说明；已有不兼容引用保留展示且标阻塞。配置一个 MCP server 的实体名称也不等于已选定其某个方法，应展示实体→发现方法→调用参数的对应关系，避免把资产名误当方法名。

“连接成功”“发现方法”“调用成功”分别报告。实际工具调用可能写数据，测试台先显示方法、参数、目标与副作用提示，只在明确发起调用后执行，连接测试不自动 tools/call。

apiKey 录入用 password/show-password，保留“已配置/替换/清除”语义；现后端已掩码返回且保留掩码更新，不应误报为读取泄密。后续通过租户 Secret 引用收敛凭证，需运行时 resolver 与迁移，不能前端把 apiKey 改名 secretRef 就算完成。

## 6. 提示词与技能

Prompt 按名称展示一行，详情提供版本列表、diff、变量表和渲染预览。新建版本默认保存为待激活，**显式激活**时展示使用该名称的 Agent 及影响；回到历史版本同样确认影响。此项改变现有“创建自动激活”的 API 语义，需要兼容字段/新版本接口及后端一致实现。

模板变量需先定义运行输入从哪里来。当前 Agent buildSystem 直接采用 p.Template，没有变量替换环节；若继续只支持静态系统提示，应明确不支持动态变量运行并对未填变量给阻塞提示。若新增渲染，后端解析、校验、预览与运行采用同一规则，传入变量与版本记入运行证据；不能只实现漂亮的预览而让真实请求仍发送模板字面量。

短期若不能改变接口，创建按钮必须写“创建并激活新版本”，提交前说明影响，不能假装已实现草稿。Agent 可选择跟随激活版或固定版本，固定版本须新增契约。保留当前 active 行为作为兼容模式。

Skill 保留说明/指令/示例/引用；增加内容差异与引用对象。停止或删除被引用资产需展示影响，不用前端缓存引用计数替代后端约束。调用前模板变量与 Skill 输入分别解释，避免把 Skill 当作可执行工具。

## 7. 资源广场

保持卡片浏览和 fork 语义，不把已安装显示成自动跟随上游更新。详情展示来源、快照版本、许可/可见范围（后端有字段才显示）、内嵌依赖、凭证剔除、待绑定数据服务、与已有同名资产的处理方式。

安装流程：预检 → 依赖与命名预览 → 安装 → 结果与待办。结果直达新资产详情，并列明需要补凭证/重绑/上传文档的对象。工作流默认停用的现有行为保留。安装不是运行。

多资产安装的原子性由后端明确：可事务处理的元数据尽量一次提交；存在部分安装则返回安装 operationId、成功/失败对象及恢复方式。前端不得在失败时无提示重新安装造成重复副本。首期只承诺结果可解释，不声称当前后端一定缺原子性。

## 8. 契约与分期

| 首期可做 | 需要后端补齐 |
|---|---|
| 主列表/引用请求隔离；持久错误态；分页；路由/操作命名；工具测试结果可见；凭证输入保护 | 就绪检查与 capabilities；输入 schema；Agent/Prompt/Skill 版本；KB 模型维度与索引来源；安装预检/结果 |
| 已有字段的依赖摘要、变量选择、空态导航 | 引用影响查询与删除限制；验证时间及结果；评估配置快照 |

不得把所有资产整理成新的 Core 大模块；资产逻辑留在各 AI 领域，横切只共享选择器、状态和引用展示组件。

## 9. 验收

- 工具引用接口 503 时工具列表仍显示，引用列标未知；主列表 403/503 不出现“暂无”。
- KB 不存在兼容 embedding 模型时能读已有 KB，创建处解释阻塞；维度不兼容由后端拒绝并定位。
- MCP 发现展示真实 schema，HTTP/builtin 不承诺未支持的测试；断连不复用旧绿色成功。
- 新 Prompt 版本保存与激活行为明确，查看引用/版本 diff 后再激活；现有按名引用兼容。
- Agent 评估结果能追溯配置，执行成功与规则通过分别显示。
- KB 检索失败/Skill 失效有运行降级提示，必需依赖按配置阻断；Prompt 预览与实际下发的渲染结果一致。
- 广场安装后能逐一补依赖，失败不显示安装完成；没有凭证/文档时不显示可用。
