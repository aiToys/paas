# 新版研发交付与流水线多视图设计

日期：2026-10-17。状态：开发交接设计，尚未实施。适用范围：`frontend/console-user-v2` 的 `/next/`，以及必要的 DevOps 插件契约增强。

事实依据与问题定位：[研发流程评审](../../reviews/2026-10-17-console-next/development-flow-review.md)。该评审是源码核对结果，演示登录失败，未完成浏览器全流程或真实集群验收；接手者必须复核当前代码，不能照历史行号盲改。

## 1. 目标与边界

用户交付目标：人工或 Agent 创建变更，明确验证结果，审批一个确定的服务版本，将同一产物晋升到目标环境，并可排障和回退。

本设计确定页面组织、主要交互、增量数据契约、迁移路径与验收标准。保留现有产品/服务模型、模板+参数覆盖、权限、租户隔离、生产写保护、构建 SSE、发布与回滚路径。沿用 PageHeader、StatePanel、TablePager、theme.css，保留经典版与全部旧深链。

第一期支持真实的顺序阶段图。自由拖拽 DAG、条件分支、并行汇合、百分比流量调度和自动指标回退属于后续能力，不得仅通过界面宣布可用。不得把所有视图堆进一个页面。

本文件是交接材料，不表示已派发其他 agent，也不授权提交、push、线上权限变更或部署。

## 2. 信息架构

全局交付中心继续承担跨产品待办和运行查询；产品内完成具体操作。产品交付采用下列任务分组，路由仍保留 `?tab=delivery&section=...`：

| 区域 | 内容 | 主要操作 |
|---|---|---|
| 交付概览 | 待我处理、当前运行、环境版本摘要 | 处理阻塞、进入具体运行 |
| 变更 | 人工/Agent 变更、按需集成批次 | 新建变更、组织批次、验证 |
| 流水线 | 定义列表、配置、某流水线的运行历史 | 预览执行计划、运行 |
| 发布 | 候选产物、环境版本矩阵、发布历史 | 晋升确定版本、回退 |
| 代码与产物 | 仓库/PR、构建、镜像 | 查看来源、构建和审查证据 |

“代码与产物”内部容纳三个辅助分区，不把管理对象再次平铺成主导航。智能研发保留快捷入口，同时是创建变更的执行方式之一；人工开发不依赖 Agent 入口。旧 `section=runs|agent|changes|pipelines|builds|releases|repos` 均可继续进入对应内容；创建显式映射，不删除旧链接。

概览没有数据时提供准确下一步：没有仓库→关联仓库，没有服务→创建服务，没有流水线→绑定模板，配置齐全→开始验证。请求失败、权限不足、未配置和零记录分开显示。

## 3. 用户流程

### 3.1 人工变更

新建变更 → 选择已有分支或创建分支 → 提交代码/PR → 运行测试验证 → 查看报告 → 按需组批或选择候选版本 → 生产审批 → 并行金丝雀验证 → 明确放量/终止 → 版本标记/主干同步。

不强迫简单服务先建批次。组批适用于多个变更共同验证；用户应能移入、移出、看冲突、调整有序合并顺序，并对修改后的批次重新验证。若后端暂不支持重排，先展示实际顺序与原因，禁止假拖拽。

### 3.2 Agent 变更

需求和验收条件 → 选择执行范围 → 生成代码与审查 → 进入同一验证/审批/发布体系。

执行范围展示四个里程碑：生成代码、验证到测试、发布到生产、标记版本与主干同步。每个选项旁展示其实际阶段与环境，后续里程碑依赖前序证据。AI 执行完成、AI 审查完成、人工验收通过和线上健康分别展示。没有结构化验收结果时显示“待验证”，不通过 agent 进程退出码推导验收成功。

### 3.3 审批与发布

审批人看清产品、服务、环境、泳道、commit、镜像 digest、验证结果和实际影响，再批准或拒绝。审批只对该目标和候选快照有效；候选、策略或验证证据版本变化后需要重新审批。

保留当前已确定的发布与主干同步顺序，按模板快照执行；若生产已更新但打版本/主干合并失败，分别显示“生产版本已更新”和“交付收尾失败”，提供明确恢复入口，不能将整个过程画成全绿，也不能无依据自动回退已运行服务。

## 4. 页面与多视图

### 4.1 流水线目录与运行历史

流水线目录列：名称、类型、目标服务/环境摘要、触发方式、最近运行、状态、耗时、运行/配置。删除收进“更多”。最近运行旁展示小阶段条，点击进入该次运行。

运行历史列：任务/流水线名称、状态与当前阻塞、服务、分支+短 commit、触发人/方式、开始时间、耗时。run ID 为辅助字段，可复制。支持状态、产品/服务、时间和触发方式筛选，筛选与分页保留在 URL。

### 4.2 单次运行：流程与步骤

保持 `/runs/:runId`，新增 `view=graph|steps|timing&stage=<run内稳定标识>`；默认 graph，小屏可自动采用纵向布局但保留用户显式选择。

```text
产品 / 流水线 / 本次任务
任务名称                状态  操作者/触发  分支/commit  时间
服务 · 实际环境 · 泳道 · 候选 digest · 模板版本

当前阻塞 / 下一步       验证依据入口       当前允许的主操作

[流程] [步骤]                    自动更新/刷新/更多
构建 → 测试部署 → 冒烟 → 上线审批 → 金丝雀 → 版本 → 主干同步
                               选中阶段
┌ 阶段详情：结果 | 日志 | 输入输出 | 关联资源 ┐
│ 目标、报告、错误、操作影响、版本与资源入口  │
└──────────────────────────────────────────┘
```

示意节点不是固定模板。真实图按 run.StageRuns 生成，不能画出未执行的质检节点。定义图、执行图分开：定义图看配置和模板约束，执行图看该次快照和真实结果。租户配置器继续覆盖参数，不能任意改平台受控阶段序列。

流程视图以文字、图标和语义色共同表示 pending/running/succeeded/failed/waiting/skipped/aborted/unknown。步骤列表使用同一节点选择和操作模型，适合键盘、小屏和完整字段检查。宽屏流程与详情可并排，小屏纵向排列；页面不横向溢出，图和日志容器独立滚动。

阶段证据链接：build→构建日志/镜像；deploy→精确 workload/实例事件；test→检查目标/实际结果；agent→Agent run/提交/审查/验收；canary→候选实例/验证地址/指标；release→发布单；baseline→实际合并提交。失败或等待节点默认选中，切视图保留 stage。

### 4.3 耗时视图（第二批）

使用真实 startedAt/finishedAt 或事件计算。区分执行耗时、等待人工决定与已知的排队耗时；不存在的事件不推算。以一个时间原点对齐节点，允许点击进入同一阶段详情。不因图形展示暗示当前引擎存在并行。

### 4.4 服务×环境版本矩阵（第二批）

矩阵放产品概览/发布页，行=服务，列=实际环境。格内展示期望/观测版本、digest、部署状态、验证结果和观测时间；默认基线，预览泳道通过筛选查看。未配置、未部署、读取失败、过期分别展示。进入格子可看发布单、来源构建、同产物晋升、工作负载、回退能力。回退产生新记录，不修改历史成功状态。

变更看板为后续可选项，不能替代上述流水线运行视图。

## 5. 三种暂停，三种决策

| 等待类型 | 界面操作 | 执行契约 |
|---|---|---|
| test/manual | 确认测试结果 / 标记不通过 | 保留兼容 approve 路径，但以 manual-test 决策类型和证据/理由记账 |
| approve | 批准上线 / 拒绝上线 | 兼容 approve；拒绝需明确决策语义，可通过新增决策接口再适配终止机制 |
| canary | 确认放量 / 终止验证 | 必须调用现有 canary promote/terminate，禁止调用通用 approve |

当前 stage 决定操作，不以 run.paused 一概显示“通过审批”。canary 面板必须显示实际环境、基线和候选、观测范围、验证地址、缺失数据；百分比流量未实现就不显示流量滑块。终止并行验证负载、终止整条运行、回退生产版本是三个不同动作。

前端按服务端能力显示禁用原因；每个操作由服务端再次检查租户、应用成员权限、生产权限、阶段及快照版本。保留现有审计；结构化决策记录补充 actor/at/reason/targetFingerprint/evidenceRefs。若启用禁止自审，由服务端执行，前端只负责解释。

## 6. 执行计划与候选产物锁定

运行前预览最终解析的模板、覆盖参数、仓库、分支/commit、服务、环境/泳道、候选产物及审批策略。占位符显示解析值与来源；不可解析的关键目标阻止执行，生产标记依据资源真实环境。

产物身份固定为 `serviceId + repoId + commitSHA + imageId + digest + sourceBuildRunId`。独立 CD 选择确定候选；AI 同次交付引用前序 build 的产物。只有构建完成后才能知道的镜像显示“由本次构建产出”，而不是预览时猜一个 latest。

生产审批前所有必要产物必须已解析并持久化，校验测试证据对应同一 commit/digest。后续阶段和原运行重试只使用锁定产物；更换候选应创建新运行/新审批。服务、仓库和产物的归属由服务端校验。相同应用下的服务 A 不得使用服务 B 的 latest-ready 镜像。

新运行保留定义/策略快照。模板升级影响后续新运行，不改变已经执行或等待审批的阶段。旧运行若缺关键快照，读页面允许降级；涉及生产的后续写操作必须先补齐并重新确认，不能自动绑定当前 latest。

预览是只读计算，不触发构建、Agent 或部署。预览与提交之间发生配置/候选/策略变更时，服务端返回冲突要求重新预览，不能静默换目标。

## 7. 增量数据与接口（待实现契约）

领域仍在 `internal/devops/pipeline` / `internal/devops/change`；不另造通用 Core 工作流引擎。memory/PG 同语义，新增字段与表使用追加 migration。

### 7.1 数据

- `DefinitionSnapshot`：模板 ID/version/hash、展开后的阶段、运行配置/策略版本；不可变。
- `ResolvedTarget`：serviceId/repoId/envId/laneId/workloadId（生成前可为空）、实际环境类型。
- `ArtifactBinding`：来源 stage/build run、service/repo/commit/image/digest、pending/resolved 状态与冻结时间。
- `CheckResult`：类型、目标、预期、实际、pass/fail/unknown/notConfigured、时间、commit/digest、报告引用。没有报告就 unknown，不读取任意 URL 或执行新命令来假装补报告。
- `DecisionRecord`：阶段、决策类型、action、actor、time、reason、快照指纹和证据引用。
- `ActionCapability`：action、allowed、reasonCode/message、目标、预期 revision。所有视图消费同一能力与阶段语义。
- 真实运行/变更事件：type、entity、occurredAt、actor、原因；旧数据只显示已知时间，不由一个 updatedAt 衍生多件历史。

input/output 可保留兼容扩展，但权威快照不能被 execApprove 等阶段重新赋值 Input 时丢失；前端展示字段与审计均脱敏。

### 7.2 接口

| 契约 | 输入与行为 |
|---|---|
| 新增 `POST /api/applications/{appId}/pipelines/{pid}/preview` | branch/commit/阶段覆盖/显式候选；返回脱敏计划、deferred 产物引用、缺配置项、能力与 planHash |
| 扩展现有 `POST .../pipelines/{pid}/run` | 接收 planHash、显式候选；服务端重算关键指纹并固化，变化返回 409；不能相信客户端计划正文 |
| 扩展 `GET /api/pipelineruns/{id}` | 返回快照、目标、候选、报告、决策、能力和观测时间，历史缺字段兼容 |
| 保留 `POST /api/pipelineruns/{id}/stages/{idx}/approve` | 服务端区分 manual-test 与 approve，阻止 canary 混用；新增字段应可兼容旧调用 |
| 保留 `POST .../stages/{idx}/canary` | promote/terminate，按真实目标复验权限和快照 |
| 新增 `POST .../stages/{idx}/decisions` | 结构化测试/上线决策及理由、expectedRevision；统一记录与既有机制适配，不能绕过权限 |
| 发布矩阵聚合 | 先评估现有 releases/workloads/服务接口；不足时新增产品级聚合读接口，保留期望/观测及部分失败状态 |

planHash 对服务器解析出的规范化定义、目标、明确候选和策略做一致性校验；未知的本次构建产物以来源引用入计划，并在构建成功后、审批前冻结。创建/决策的并发与幂等在后端保证，重复提交不重复构建或放量。新增契约必须登记 route registry 并生成类型，不维护另一份接口清单作为真源。

## 8. 质量与视觉基线

指定健康路径失败不能无提示地用 `/` 成功替代；回退策略须显式配置并记录实际路径。冒烟探活、单测、覆盖率、安全检查、AI 验收与人工确认分别展示，具体执行器未接入前标未配置。

复用现有语义 token 和公共组件。主要按钮聚焦当前动作；长 ID/镜像可复制，状态不只靠颜色。表格放 table-scroll。日志错误与正文分开，跟随可暂停。切换 runId/stage、关闭、卸载后旧请求不能覆盖新对象；终态停止轮询，页面隐藏暂停，权限变化后重新获取能力。403/404/网络失败分别呈现。

保留真实资源目标，不把顶栏浏览环境当写目标。对已有完成的构建日志、回滚、PR 审查和服务运维入口做回归，禁止为完成本设计覆盖其他 agent 工作。

## 9. 验收与交付

- 人工创建变更、组批/移入移出、冲突后重试可在新版完成。
- 三种暂停展示正确动作；canary 不调用 approve；没有能力时显示原因。
- 审批等待期间出现新构建，原运行的候选和放量 digest 不变；多服务产物不串用；重试不重新选 latest。
- graph/steps 展示相同阶段、状态、选择与动作；旧深链可用，小屏和键盘可操作。
- 从失败节点到日志/实例事件 ≤2 个动作；配置齐全时测试部署 ≤5 个主要动作、≤2 次页面切换。
- 假时间线、成功枚举错配、读失败假空态和同路由切换残留修复。
- 验证 390/768/1024/1440px、亮暗主题、viewer/developer/admin、生产拒绝和过期会话。
- 产物不漂移、同目标并发、拒绝与撤权、模板升级、部分成功必须有针对性测试。
- 单元、PG、前端、浏览器、真实集群证据分开记录；没有环境就明确待验证，不能以截图/HTTP 200 替代全链路验收。
