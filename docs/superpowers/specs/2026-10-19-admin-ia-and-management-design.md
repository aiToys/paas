# PaaS 管理后台：信息架构与管理能力统一优化设计

日期：2026-10-19。状态：设计交付，等待其他 agent 实施。范围：console-admin、后台管理 API 契约及与新版用户端的衔接；本次只新增设计文档与交互原型。

## 1. 结论与设计目标

需要优化，而且不只是重排菜单：当前后台能维护部分平台目录、查看租户资源，但缺少统一的租户上下文、跨模块排障链路，以及工作流、配置发布、告警事件、备份恢复等管理闭环。

推荐将后台明确为「平台运营中枢」：管理供给、开通租户、定位异常、执行受控干预、核查用量与审计；用户端继续负责产品开发与日常自助。沿用新版用户端的名称、状态语义与交互习惯，不将用户端所有编辑器复制到后台。

验收目标：

- 普通导航最多「管理域 → 页面」两层；页内类型切换使用 tab，实体关系放在详情中。
- 从租户进入其资源、用量、审计不再手输 tenant ID；从异常进入准确实体详情最多两次点击。
- 全部原有后台能力有迁移落点，既有深链接可继续访问。
- 已受理、执行中、真实生效分别表达；未知、未接入、读取失败不显示为健康或零。
- 管理能力缺口逐项注明接口基础与优先级，实施 agent 不需要再次猜测业务边界。

| 既有边界 | 延续 `2026-08-07-admin-management-foundation-design.md`：看穿 + 干预 + 基础设施代建；不代建产品、业务流水线或发布编排 |

工作树里的备份、配置、治理、可观测等最新代码仍有未提交变更，本设计将其视作「代码可见能力」，不视作 CI、真实供应商或集群验收通过。尝试启动当前后台 Vite 预览时本地端口绑定被沙箱拒绝，未继续占用其他会话服务；现状判断以源码为准，浏览只作补充。

## 3. 当前主要问题

| 编号 | 发现 | 对操作的影响 | 设计决定 |
|---|---|---|---|
| I01 | 资源总览 → 应用运行态 / DevOps 链路 → 叶子，混用实体分类和任务分类 | 高频页面要反复展开，跨域排障困难 | 取消第三级，运行、交付与基础设施直接归对应管理域 |
| I02 | 「智能体」实际包含 Agent、技能、工具、知识库、提示词、广场 | 标题不能解释内容，工作流仍遗漏 | 改「AI 资产」，广场独立，执行记录归 AI 运营 |
| I03 | AgentRun 放 DevOps 下，但既有自动审查也有通用 AI 执行 | 按执行技术找路，而非按运营任务 | AI 执行统一入口，按来源类型分 tab，不合并不同数据语义 |
| I04 | 引擎目录独立顶级，配置名为「命名空间」，安全叫「密钥」 | 供给与消费割裂，术语与新版用户端不一致 | 引擎进入数据服务；配置中心注明当前覆盖范围；凭证与 API 密钥分开 |
| I05 | 多个列表反复输入租户 ID，租户列表只有创建/删除 | 客服或运维要凭记忆串联用户、产品、资源、账单 | 租户详情成为运营工作区，提供共享浏览范围与名称选择器 |
| I06 | 构建、镜像、发布、流水线运行各自独立列表 | 同一故障链被拆断 | 交付记录四个 tab + 有 ID 的关联跳转 |
| I07 | 首页欢迎、图表、个人中心占据主位，趋势与正常动态缺实证 | 难以回答「先处理什么」，且可能误判健康 | 关注事项优先；删除推算趋势及固定正常结论；展示数据新鲜度 |
| I08 | 后台有告警规则、无统一当前告警/历史/采集质量视图；配置和治理也不完整 | 只能看对象存在，不能判断是否生效 | 补管理详情与结果反馈，按能力矩阵分期 |
| I09 | 应用详情含「绕过 prod:write」「级联清理+回收配额」等实现词汇 | 用户需理解内部实现才能判断风险 | 改为租户、环境、影响对象和操作结果的业务语言 |
| I10 | 菜单 API 无角色过滤；前端有权限元数据机制，但菜单未声明 | 用户能看到无法访问的模块；搜索/快捷入口易与权限脱节 | 同一能力目录驱动导航、搜索和快捷入口，服务端权限仍最终裁决 |

## 4. 后台与新版用户端的职责映射

| 新版用户端任务 | 后台对应职责 | 共享语义 | 后台不新增的日常业务操作 |
|---|---|---|---|
| 产品、工作负载、交付中心 | 跨租户运行排障、交付追踪与必要干预 | 产品 = 当前 application 实体的展示名称，工作负载/服务不混用 | 不再建一套产品开发、代码编辑或发布编排工作台 |
| 模型目录、Playground | 模型供给、通道和供应商配置、连接诊断 | 同一模型 ID、能力、价格单位、可用状态 | 不增加另一个顶级 Playground；按模型提供明确的诊断入口 |
| AI 开发、资源广场 | 资产关系、执行故障、广场治理 | 智能体、工作流、工具、知识库、提示词、技能 | 不复制工作流画布，不替租户改提示词内容 |
| 数据服务、环境 | 引擎供给、跨租户运行、代建、备份、泳道资源回收 | 引擎与实例、物理环境与泳道分别表达 | 不将 Environment.Cluster 字符串包装成已实现的多集群纳管 |
| 配置中心、流量治理、可观测 | 生效状态、影响面、故障证据与受控处置 | 草稿/发布/生效；期望状态/实际状态 | 不由平台管理员日常代写业务配置或路由 |
| API 密钥、密钥与凭证、用量与配额 | 跨租户授权、平台凭证、消耗归因及账单核查 | 入站 API 密钥与出站供应商凭证严格分开 | 不将 tokens、估算成本、计费记录和现金收入混为同一指标 |

## 5. 推荐菜单（目标态 23 个入口）

```text
平台总览

租户与访问
  租户管理
  用户与授权
  API 密钥

AI 运营
  模型与通道
  供应商
  AI 资产
  执行记录
  资源广场

应用与交付
  产品
  工作负载
  交付记录
  流水线模板

基础设施
  数据服务
  环境与泳道
  配置中心
  流量治理

用量与账单
  用量与配额
  账单

安全与运维
  凭证与证书
  可观测
  审计日志
  平台诊断
```

目标为平台总览 + 六个职责域，共 23 个叶子入口。侧栏只展开当前域，保留展开记忆；1440px 默认展开文字侧栏（约 228px），允许手动收起但图标必须带名称提示。1024px 以下抽屉导航；列表独立横向滚动。入口数量不是硬性 KPI，**没有真实数据源的新入口不提前上线为占位页**。

页内收敛：用户与授权 = 用户 / 内置角色与权限；数据服务 = 实例 / 引擎目录 / 备份恢复；环境与泳道 = 环境 / 泳道；交付记录 = 流水线运行 / 构建 / 镜像 / 发布；AI 资产 = 智能体 / 工作流 / 知识库 / 工具 / 提示词 / 技能；可观测 = 当前告警 / 历史事件 / 指标 / 日志 / 链路 / 规则 / 采集诊断。

这些 tab 是按需浏览的同类内容，不在首页同时渲染全部列表；可观测小屏允许横向滚动 tab。详情页面包屑可超过两段，侧栏本身不再嵌套第三层。

## 6. 管理能力盘点与缺口

证据分级：**A** = 管理端接口和 UI 已有，优化组织或交互；**B** = 部分后台接口/领域能力存在，需聚合、补详情或独立管理接口；**C** = 缺少后台契约或领域语义，需新增设计与实现。B/C 均不代表仅加按钮即可完成。P0 = 正确性/既有能力整理，P1 = 运营必需闭环，P2 = 深化能力。

| ID | 能力与当前基础 | 需要补足的管理能力 | 级别 / 优先级 / 落点 |
|---|---|---|---|
| M01 | 租户已有列表、创建、删除；Tenant 无状态 | 租户详情：用户、产品、资源、用量、账单、审计聚合与开通引导 | B / P1 / 租户管理 |
| M02 | 无租户冻结状态；删租户主要检查身份库用户 | 冻结/恢复的作用范围、全资源依赖预检、保留/清理策略；禁止做“一键删租户全资源” | C / P2；删除预检 P1 / 租户详情 |
| M03 | 用户 CRUD、禁用、内置角色读取均已有 | 用户授权摘要、所属租户可读名称、角色权限矩阵；角色只读明确标识 | A / P0 / 用户与授权 |
| M04 | 菜单全量下发；已有前端权限过滤机制和后端 super_admin 校验 | 菜单/搜索/快捷入口同源按能力过滤；平台身份与 tenant-admin 分清 | B / P0 / 全局；不据此新增权限 |
| M05 | API Key 已签发/撤销，模型中无 expiresAt/lastUsedAt | 先补归属展示与吊销影响；到期、最近使用、无停机轮换需新数据模型，已有 JWT 会话失效语义需单独验证 | A+C / P1→P2 / API 密钥、用户详情 |
| M06 | 模型、通道、供应商 CRUD 与路由刷新已有 | 同页显示通道、凭证配置、优先级、引用模型；连接诊断单独触发，保留失败原因 | A+B / P1 / 模型与通道、供应商 |
| M07 | 通道 healthy/degraded/offline 是配置及请求结果状态；无统一持续探活证据 | 区分配置状态、最近实际请求、探测时间；模型启停、供应商变更影响面及存量通道同步预览 | B+C / P1→P2 / 模型详情；先做诊断与影响可见 |
| M08 | AI admin handler 仅 GET 五类资产和广场，缺 workflow；UI 关系只基于有限全量列表推算 | 补工作流定义列表、脱敏详情、跨资产引用和文档索引状态，不复制编辑器 | B / P1 / AI 资产 |
| M09 | 外部 AgentRun 有列表和来源 token 汇总；原生 Agent SSE 与 WorkflowRun 是不同执行系统 | 工作流运行列表/节点失败/等待确认/中止；原生 Agent 运行持久化若无则另补；不能把外部来源前缀当租户归因 | B+C / P1 / 执行记录 |
| M10 | 广场已有 admin 只读列表；租户下架端点支持 admin 判定但无独立后台治理闭环 | 脱敏快照、引用/安装影响、平台下架理由及审计；恢复/审核流程为后续新状态机 | B+C / 下架 P1、审核 P2 / 资源广场 |
| M11 | 产品与工作负载已有详情、扩缩容、日志及删除；租户侧运行运维更丰富 | 产品聚合到服务/环境/泳道，后台实例事件/操作结果；后台重启/重建/终端必须单独补受控契约 | A+B / P1 / 产品、工作负载 |
| M12 | PipelineRun、构建、镜像、发布后台可读；发布回滚已有；后台运行接口主要只读 | 合并交付链路，补准确关联；后台终止/重试有必要但需独立权限审计；不默认代审批生产发布 | A+B / P0→P1 / 交付记录 |
| M13 | 用户端有变更、集成批次、仓库与 PR、webhook；后台无对应跨租户工作区 | 变更/批次异常只读追踪、webhook 最近失败与凭证状态；可重放操作需幂等及独立契约 | B+C / P2 / 交付记录详情、平台诊断 |
| M14 | 公共流水线模板已有 CRUD，内置模板保护已有 | 展示使用方、版本和删除/变更影响，避免静默影响租户编排 | A+B / P1 / 流水线模板详情 |

### 6.1 额外纳入，但不扩大为本期重建的平台

- 私有化与 SaaS：诊断页显式展示部署模式、可用能力与离线依赖，不以公网 CDN 文档或外部服务可达为默认条件；airsync 的包版本/完整性报告可以作为只读诊断输入，不能从页面直接触发集群升级。
- 资源生命周期：删除模型/凭证/引擎/环境/租户前返回引用清单；优先阻止危险删除，不能用“同时删掉所有引用”规避关系问题。
- 运维作业：备份、恢复、重启、重建、reconcile 统一展示操作 ID、目标、操作者、开始/结束、结果与后续证据；不立即另造横切任务引擎，先适配各领域已有异步记录。
- 成本语义：外部 AgentRun token 是上游统计；原生路径可能为估算；账单金额是平台计费记录；没有真实结算与对账数据前不能显示“营收”或“供应商毛利”。
- 商业后台深化：自定义平台运营角色、会话撤销、SSO、预算、供应商结算、通知渠道/抑制策略为 P2 独立能力；需要数据模型/执行机制，不用空菜单占位。
- 未采纳：独立顶级「集群/GPU/节点管理」、完整备份调度系统、任意平台配置在线编辑、另造工单/审批平台；当前源码不足以支撑，先在诊断或领域详情中表达真实边界。

## 7. 全局交互与权限设计

### 7.1 一个浏览范围，明确哪些页面适用

顶栏提供「浏览范围：全部租户 / 租户名称」；租户资源类页面再提供环境过滤。列表页不重复出现另一个 tenant ID 输入框。平台模型、供应商、引擎、平台凭证等共享供给页显示「平台级，不按租户过滤」，保留浏览选择但不误过滤。

进入租户详情只将该租户作为详情局部上下文；点击「查看该租户资源」才显式带上 tenantId 并进入范围视图。浏览范围始终是过滤器，**不能改变登录身份、资源归属或写入目标**。从 URL 回放的 tenantId/envId 必须在服务端校验。

切换租户：清空不属于目标租户的环境、产品、勾选行、打开抽屉；取消旧请求或以请求序号丢弃旧响应。来源未知的外部 AgentRun 放在「平台执行域」，选单租户时不得继续混入并标成该租户记录。

### 7.2 搜索和详情

- 顶栏 Cmd/Ctrl+K 搜索菜单、术语别名和已授权实体；先做本地导航搜索，后做受权限控制的实体检索。不为实现搜索在浏览器预拉所有租户敏感列表。
- 名称匹配优先于组名；搜“引擎”直达数据服务·引擎目录，搜“提示词”直达 AI 资产·提示词，搜“角色”直达用户与授权·内置角色。
- 普通详情复用现有抽屉，宽度 min(960px, 92vw)，`?id=<id>` 驱动打开；日志、运行链、版本 diff 等长任务使用独立隐藏详情页，避免多层抽屉。
- 表头统一：名称（可点）/ 所属租户 / 产品或环境 / 状态 / 更新时间 / 操作；ID 作为名称下方次级信息并可复制，不占默认第一列。
- 筛选、排序、分页、tab 与详情 URL 同步；返回后保留列表滚动及筛选；无结果提示「清除筛选」，无资源提示对应可用创建/开通路径，失败展示重试。

### 7.3 身份与授权

本期平台写操作继续采用真实 `gateway.IsPlatformAdmin` / `adminGuard` 语义；租户管理员不是平台超管。修正菜单返回与前端权限表述不一致的问题，但不通过隐藏菜单替代 API 校验，也不将 tenant-admin 自动提权。

目标能力元数据至少包含 `navGroup`、`title`、`keywords`、`parentNav`、`scopeKind`（platform/tenant-filtered/execution-domain）、`requiredPermissions`；与现有 MenuDTO/RouteMeta 集成，由后端返回已授权目录。新枚举和字段应落实 Go 与 TS 契约，避免再建一份仅前端硬编码业务菜单。

P2 如果引入平台只读运维、资源运维、财务、安全管理员，必须同步后端细粒度鉴权、种子/迁移与审计；本期原型中的“只读/可干预”表示页面能力，不声称这些新角色已存在。

### 7.4 操作与结果

详情头固定显示租户、产品、真实环境、资源 ID；生产状态使用文字 + 状态色。运维按钮先展示影响，危险操作在「更多」中；输入名称确认用于删除/恢复/生产重大变更，不给只读浏览加确认。

异步操作展示「已受理 → 执行中 → 已生效 / 失败 / 状态未知」。HTTP 200 或数据库更新仅能证明受理/保存，最终依据来自 Job、Workload 操作记录、CRD/控制器或供应商返回。无可观察执行状态的能力不标“已完成”。失败保留目标与错误，不自动重放危险命令。

平台代建只支持数据服务/环境：必选目标租户、真实环境、规格，展示该租户配额影响；产品、工作负载业务创建、日常配置发布仍由租户负责。跨租户应急写操作需独立端点、资源归属反查、白名单 action、原因、审计 actor/targetTenant/env/resource/requestId，不能借浏览范围冒充租户。

「查看用户端」只打开同源 `/next/` 的相应路径；已有会话有权限才可访问，无权限正常拒绝。不要附加 Token、不要静默切租户、不实现冒名登录。

P0 即移除推算涨幅和曲线、固定“所有服务在线”。已有快照卡保留，但每张卡注明含义与来源失败；P1 引入聚合接口时支持部分成功、source/observedAt/coverage。状态失败不归零，当前运行数不能反称“失败数”。关注事项第一期只接可靠的失败/暂停运行、配额阈值和失败任务；当前告警有独立后台接口后再接入。

### 8.2 租户详情：运营工作区

页头「Acme / t-acme」+ 当前状态（无状态模型时不伪造“正常”）+「查看该租户资源」。tab：概览 / 用户与授权 / 产品与资源 / 用量与账单 / 审计；概览以开通清单替代大图表。

开通步骤：创建租户 → 创建管理员 → 检查配额 → 按需分配环境/数据服务 → 交付登录入口。每步可独立重试，已有成功步骤保留；用户密码不经 URL 或审计明文传递。租户冻结待 M02 实现后出现，删除前展示用户、产品、资源、任务、未结账单等依赖。

### 8.3 模型、供应商、凭证连成一条配置链

模型列表：名称/能力/供应商数/配置状态/最近诊断（若无则“尚未诊断”）/价格；详情默认「通道」，旁边「模型信息 / 变更记录」。通道显示供应商、上游模型、配置优先级、凭证引用、实际请求/探测证据。

供应商详情展示关联通道与受影响模型；修改 BaseURL/凭证先展示**当前写入是否只影响新通道**，不得暗示存量已同步。凭证缺失时可从表单打开平台凭证创建抽屉，成功后回填 credentialRef 并保留原草稿；供应商凭证不混进 API 密钥列表。

连接诊断为显式操作，注明可能产生模型调用；超时与失败原因脱敏，不能因保存成功变成绿色“可推理”。没有真实探活接口前仅显示“已配置 / 缺少凭证 / 未诊断”。

### 8.4 AI 资产、执行与广场

资产默认列名称、类型、租户、引用数、模型、配置状态；详情展示引用图的列表形式（上游模型/提示词/工具/知识库/工作流），不做巨大无导航关系图。缺少完整查询的引用数标“当前已加载”，跨租户 ID 不能只用裸 ID 关联名称。

执行记录按来源区分「外部 AgentRun / 工作流运行 / 原生智能体运行（有持久化后）」；字段不适用显示“未提供”，不能造统一 Token/租户归因。工作流详情默认失败或等待节点，输入输出脱敏，暂停等待业务确认不默认算故障；平台仅在管理契约允许后提供中止，不代业务审批。

广场独立展示已发布内容、发布租户、实体类型、引用与安装量；首期补下架的影响确认与理由/审计。审核、封禁、恢复均待生命周期实现，不能加无效按钮。

### 8.5 数据服务、备份与环境

数据服务页提供实例/引擎目录/备份恢复，tab 共用合适的筛选而非强制所有字段同构；引擎是平台级，切到引擎时明确租户过滤不生效。实例详情：运行概览 / 实例与日志 / 备份恢复 / 操作记录。

备份表列模式、资源/租户/环境、状态、产物字节数、校验时间、最近恢复任务；`record` 标“记录，无备份产物”，`snapshot` completed 也只表示产物完成，校验和通过不等于恢复演练通过。恢复到新实例，确认源快照、目标租户/环境、支持引擎、配额及产物可访问性；不提供覆盖生产库的快捷动作。

环境与泳道分开 tab；泳道展示所属环境、到期时间、访问入口、工作负载/路由引用、回收结果。关闭先展示依赖和回收计划；生产禁建泳道规则不因管理员页面改变。Environment.Cluster 仅物理落点说明，集群健康另从真实诊断来源读取。

### 8.6 配置、流量与排障

配置中心详情按「草稿 / 已发布 / 引用与影响 / 发布记录」组织，环境/泳道为精确实体。敏感值掩码，diff 允许看键变化而非明文。后台先只读，回滚在独立端点实现后开放。

流量治理分「注册服务 / 路由 / 熔断」；实际观察状态、期望版本、已应用版本、最后错误并列，不用单个 enabled 表示已经下发。已有注册删除能力迁移完整，新增路由/熔断不能复用租户 API 假装跨租户。

可观测从当前告警进入资源 → 实例日志 → trace；全程携带 tenantId/envId/resourceType/resourceId/timeRange，TraceID 查询需服务端确认可见范围。采集诊断明确 ok/empty/failed/disabled/stale。规则配置与告警事件不同，不把“有规则”计成“发生告警”。

### 8.7 用量、结算与平台诊断

用量与配额：用量分析 / 资源配额两 tab，先展示已有资源计数，Token 分析在真实管理聚合完成后上线；每指标注明周期、单位、估算/实测与更新时间。账单是记录核对，“标记已结算”是人工登记，不伪装为真实支付扣款；结算理由/凭据与审计需补契约。

平台诊断第一期只读：版本与构建、数据库连接/迁移、K8s 数据面与 RBAC、registry、AgentRun、供应商配置状态、可观测后端、工作负载漂移。缺接口项展示“尚未接入诊断”而非绿色。修复命令独立于只读检查；原 reconcile 为写操作，有确认与结果，补 dry-run 前不得称可预览。

## 10. 可执行验收标准

1. 当前26个可见叶子与隐藏模型详情、个人中心、成员表均有迁移记录；旧链接、tab、query、hash、登录回跳和浏览器返回均有效，无新增死链。
2. 选择租户后，产品→工作负载→交付→审计保留范围；切租户后无旧实体/环境/抽屉/请求结果泄入；平台目录显式显示不适用过滤。
3. 普通租户管理员、developer、viewer 不获得新增后台权限；菜单、快捷入口和搜索一致，手输后台 API 仍拒绝；未知资源继续按既有隔离约定处理。
4. 搜“引擎/角色/提示词/备份”能直接进入准确 tab；实体资源按授权检索，键盘可完成打开/关闭/返回，焦点恢复。
5. 从首页异常进入准确运行/资源最多两次点击；详情后返回保留列表筛选、页码、选中项定位，切换来源明确。
6. 首页没有推算涨幅/曲线和固定正常文案；每个来源失败、未接入、过期独立表达；部分失败不抹掉成功分区，也不以0掩盖失败。
7. 模型保存后显示配置状态，真实诊断单独标时间/结果；凭证补建后表单内容不丢失；未证明存量通道同步时明示影响边界。
8. 原生/外部 AgentRun/工作流的数据不虚构合并；外部无租户归因的记录不出现在单租户统计；未持久化的历史明确不可查询。
9. 配置 diff、引用、发布记录和治理 apply 证据可查；任何新跨租户写接口有独立权限与审计，不能复用浏览范围转租户写。
10. record 备份无恢复入口；snapshot 的产物完成、校验和、恢复任务分别展示；恢复创建新实例，不覆盖原生产实例。
11. 异步运维操作只有观察到实际结果才显示已生效；未知状态可继续查询；无安全重试语义时不自动重试。
12. 1440/1024/768px 可用；长租户/产品名和ID不挤压操作；状态同时有文字；表格滚动、键盘焦点、亮暗主题与可读性完成目视验证。

本次交付不执行这些业务验收；实施阶段按任务运行后台 type-check/build、相关 Go/前端测试与浏览回归。真实供应商调用、生产运维、恢复演练、支付/结算、集群部署分别列证据与授权，不能用本地测试替代。
