# 专项 03：模型能力匹配、试用与调用诊断

状态：设计交接；依据 MD-01/02/03。

## 1. 首先修正的行为

模型目录已经有能力过滤和通道状态，但统一进入 Chat Playground；Playground 当前把字符数标为 tokens，并把 HTTP 错误作为 assistant 文本写入历史。先修这些正确性问题，再扩展多模态试玩。

通道 healthy/degraded 是平台目录提供的状态，不足以证明当前用户有权限、凭证有效、当前请求协议被供应商支持。模型目录、运行检查、一次请求结果分别表达。

## 2. 目录与模型详情

保留表格默认视图。列为模型/主要能力/上下文或输入约束/价格口径/路由状态/操作；能力很多时摘要＋详情，不挤满一行。模型名进入详情侧栏或独立页，展示支持 API、参数限制、输入输出类型、接入示例、当前用户可执行动作。

主要动作按**平台当前实际支持的端点**决定：

| 能力与平台支持 | 主要动作 |
|---|---|
| Chat，平台已支持 | 对话试玩 |
| Vision，平台支持图像输入 | 多模态试玩；不支持则展示接入/缺少适配的说明 |
| Embedding，平台端点已支持 | 向量测试，文本批次与维度结果，不展示对话输入框 |
| 图片生成，平台端点已支持 | 图片生成表单及结果；不支持则不能发送 chat 请求代替 |
| 未知/其他能力 | 查看 API 接入与支持范围；能力有标签不代表试玩已实现 |

能力不兼容的历史 `?model=` 链接应解释并引导到正确模式，不静默换模型。价格单位按真实契约表达：输入/输出 Token、张数或其他计价单位，缺价格显示“未提供”；不把 image/embedding 全部套双向百万 Token 价格。

## 3. Playground 布局与交互

```text
Playground       模型/Agent [选择]       能力：对话      [接入示例]
本次配置：模型 xxx · 当前身份可调用/尚未验证 · 新会话
──────────────────────────────────────────────────────────
会话与结果（主区）                    │ 参数与请求证据（可收起）
用户消息                             │ 模型参数 / 生效限制
回答 / 推理内容折叠                   │ 首字延迟、总耗时
错误卡（独立于模型消息）              │ usage / requestId / 状态
输入区 [发送 / 停止]                  │ 脱敏请求示例与错误详情
```

消息模型增加 status（pending/streaming/succeeded/failed/cancelled）与独立 error 元数据；构建历史只取可继续对话的用户消息与成功回答。失败/错误卡不发给模型，失败请求重试要避免重复添加相同用户轮次。停止后保留部分输出并标“已停止”；是否把部分输出用于下轮由明确规则决定，默认不当成完整回答。

SSE 断流与正常 DONE 分开；后端 error 事件、无 body、HTTP 非 2xx、解析错误提供具体说明，未知错误保留 requestId（若有）。503 不直接判定凭证未填，可能是限流、超时、所有通道不可用；引导遵循当前角色，有管理员可达入口才链接，不再使用旧“平台能力→安全”菜单名。

切换模型/Agent 时提示当前会话处理方式，默认新会话，用户可以显式保留上下文并了解参数变化。模型支持的参数才开放，未知限制不硬套；Agent 列表过滤停用项并说明依赖阻塞。已有停止、推理内容折叠能力保留。

## 4. 用量与证据

立即可完成：把现有字符计数显示为“输出字符”，不显示 tokens 或推算费用。若上游/网关返回 usage，则分 input/output/total、标数据来源与是否最终值；无 usage 显示“未返回”，不填 0。流式 usage 需要请求选项和事件契约支持后再实现。

预估 Token 必须明示估算方法与范围，不能用于账单或跨模型速度比较。精确 tokens/s 仅在精确 usage 和时间边界可用时展示；当前可显示首字延迟、总耗时、字符吞吐并标单位。

诊断区区分用户可修（输入/参数/额度）和需管理员处理（供应商/凭证/协议）；不暴露上游密钥或内部敏感响应。接入示例默认使用环境变量占位符，用户显式复制，不在页面生成长期明文凭证。

## 5. 契约边界

ModelInfo 需要补充 supportedEndpoints、输入输出类型、参数限制、计价单位/币种/数据版本，以及检查证据时间；字段缺失时保守呈现。供应商、通道和凭证 CRUD 留在管理员控制台，本专项不迁入用户台。

请求诊断可返回 requestId、traceId、usageSource 与可公开错误分类；所有新增字段经 route registry/OpenAPI 与生成类型。前端错误隔离与字符文案可先完成，不依赖目录扩展。

## 6. 验收

- 连续两轮请求中第一轮 503/400：第二轮请求体不包含系统错误提示；重试不重复用户消息。
- 正常 DONE、断流、主动停止、供应商错误分别显示；不能将断流输出标完整成功。
- 中文、英文、emoji 输出按字符计数，label 为字符；仅有真实 usage 时标 Token，未知与 0 区分。
- 从目录选非 chat 模型，不会盲发 `/v1/chat/completions`；不支持的能力明确说明。
- 无权限用户可以看目录时仍可看信息；试玩受后端权限限制，错误引导不泄露供应商凭证。
- 模型切换、长输出、暗色/亮色与窄屏下，输入和停止始终可达。
