# console-user 信息架构按操作频率重组

> 日期：2026-08-06
> 范围：仅 console-user（开发者控制台）。console-admin 不在本期（P1.4 刚做完菜单三级重构，频率模型不同）。
> 方案：轻量重组 —— 侧栏按频率三段分层 + 资源组折叠记忆；应用详情头部去动作化 + 压成面包屑紧凑条。

## 背景

开发者以应用操作为主，但当前 console-user 有两个空间利用不合理之处：

1. **侧栏**：8 个顶级项里，资源中心(6 子) + 工作负载(3 子) + 平台能力(4 子) 三个折叠组共 13 个子项**永远铺开**，占侧栏 ~70% 纵向空间。这些都是「创建后很少反复访问」的资产 / 横切能力（低频），而真正高频的「应用」（主线）被淹没在平级列表里，没有视觉优先级。

2. **应用详情头部**：独立大卡片（大图标 + 名称行 + 描述行 + `[监控][部署][删除应用]` 按钮行），加 tab 行 = 两整行，吃掉首屏 ~120px。且：
   - `监控` 按钮冗余 —— 应用内已有「可观测」tab（含「在监控大屏中打开」出口）。
   - `部署` 按钮冗余 —— 只是切到「部署」tab，点 tab 即可。
   - `删除应用` 是低频高危，却与高频按钮平级占位。

应用详情已是 11 tab 工作台，**tab 即能力**，头部不该重复 tab 已有的动作。

## 目标

- 侧栏按操作频率分层：高频主操作置顶并强化「应用」，低频资源/能力组默认折叠（记忆展开态），回收侧栏空间。
- 应用详情头部去动作化 + 紧凑化：压成面包屑身份条，回收首屏垂直空间；监控/部署 删按钮（tab 覆盖），删除应用降权到次级入口。

## 非目标（留后续）

- 命令面板（Cmd+K）、上下文导航重构（激进方案，本期不做）。
- console-admin IA 调整（频率模型不同，P1.4 已重构）。
- 「编辑应用 / 导出配置」端点（需后端补 PUT /api/applications/{id}，下拉位预留）。
- 应用详情 tab 分组 label 的进一步压缩（运行态/资源/DevOps 三组 label 保留）。

## 设计

### A. 侧栏 IA 重组（`App.vue`）—— 按频率三段分层

```
── 主操作 ──（高频开发动作，永远可见）
  ● 应用          ← 视觉强化（brand 色左条 + 字重 600，主线锚点）
  ● DevOps
  ● Playground
  ● AI 服务       ← 模型市场（与 Playground 配套，「用模型」高频）
── 资源与能力 ──（创建后少动，默认折叠，各自记忆展开态）
  ▸ 资源中心 (6)   ← 点击组标题 toggle 展开/收起子项
  ▸ 工作负载 (3)
  ▸ 平台能力 (4)
── 环境 ──
  ● 环境
─────────────
设置: API 密钥 · 配额与账单
```

**关键改动**：
- 当前三个资源组的子项**永远铺开**（`.sub-nav` 始终 render，13 项占满侧栏）→ 改成**可折叠**：点击组标题 toggle，默认全折叠。
- **记忆**：每组展开态持久化 `localStorage`（key `paas:nav-open:<group>`），用户展开过的组下次保持。封装到新 composable `useNavState.ts`。
- **「应用」强化**：主操作区首项，brand 色左竖条（复用现有 `.nav-bar.active` 视觉）+ 字重 600 + brand 色，视觉上明确「这是入口」。
- 加两个分组 section label：「主操作」「资源与能力」（复用现有 `.nav-section-label` 样式，与「设置」label 同款）。
- 折叠态（侧栏收起成图标条）：保持现有 `collapsed` 逻辑，资源组折叠交互仅在展开态生效。

### B. 应用详情头部去动作化 + 面包屑紧凑条（`ApplicationDetail.vue`）

```
← 应用 / app-cs  [prod] ●健康                        ⋯
─────────────────────────────────────────
运行态: 概览 部署 服务治理 可观测
资源:   资源绑定 配置 用量
DevOps: 代码仓库 构建 镜像 发布
```

**改动**：
- **删掉独立 header 大卡片**（大图标 + 名称行 + 描述行 + 按钮行）。
- 改成**面包屑紧凑身份条**（一行，紧贴 tab 行）：
  - `← 应用 / <应用名>`：返回箭头 + 「应用」面包屑（点回应用列表）+ 当前应用名。
  - `[环境]`：环境 chip（复用环境类型着色，prod 红）。
  - `●健康`：健康状态点 + 文字（复用现有 `statusLabel` + `pulse-dot`）。
  - 右端 `⋯`：`el-dropdown`，内放 `🗑 删除应用`（danger），`confirmDangerous` 逻辑不变。
- **删掉 `监控`、`部署` 两个按钮** —— 能力已被「可观测」「部署」tab 覆盖，零功能损失（监控大屏出口在可观测 tab 内已有）。
- **应用描述（`app.desc`）**：从 header 移除，归到「概览」tab 展示（概览本就该有应用说明）。
- **回收空间**：从两整行（header 卡片 + tab 行）压成「一行身份条 + tab 行」，省 ~70px，首屏 tab 内容显著增多。

### C. 折叠态记忆 composable（新增 `composables/useNavState.ts`）

- 封装 `localStorage` 读写 + reactive `Set<string>`（哪些资源组展开）。
- 默认：三个资源组（`resources`/`workloads`/`platform`）都折叠。
- `toggle(group)` / `isOpen(group)` 接口，`App.vue` 消费。

## 改动清单

### 前端（`frontend/console-user/src/`）

| 文件 | 改动 |
|---|---|
| `App.vue` | nav 数组重组三段（主操作/资源与能力/环境）；资源组改可折叠（toggle + 记忆）；「应用」视觉强化；加「主操作」「资源与能力」section label |
| `views/ApplicationDetail.vue` | 删 header 大卡片 + 监控/部署/删除按钮；改面包屑紧凑身份条；描述移到概览 tab；删除应用进 `⋯` 下拉 |
| `composables/useNavState.ts` | **新建**：资源组折叠态记忆（localStorage） |

### 后端

- **零改动**。

## 验证

- 前端 `vue-tsc --noEmit` + `pnpm build` 三套通过。
- k8s e2e（`./scripts/deploy-k8s.sh`）：
  - 侧栏：主操作区（应用强化/DevOps/Playground/AI 服务）置顶；资源中心/工作负载/平台能力默认折叠，点击组标题展开子项，刷新后记忆展开态。
  - 应用详情：头部为面包屑紧凑条（返回 + 应用名 + 环境 chip + 健康 + ⋯），无大卡片；监控/部署按钮已删（用 tab）；描述在概览 tab；⋯ 下拉点开有「删除应用」，输入应用名确认可删。
  - 首屏 tab 内容垂直空间较改前明显增多。
