# 泳道与访问地址体验设计

日期：2026-10-17。状态：设计交接，未实施。范围：新版 `/next/`、泳道/访问地址读模型及必要的路由语义改进。用户明确要求只出设计，开发由其他 agent 完成。

## 1. 结论与边界

保留“同环境内只部署变更服务，其余服务复用基线”的方向。泳道不是必须复制整套环境的昂贵资源，也不是 Git 分支本身。

当前应优先改进：稳定的泳道身份、同环境内的明确回退规则、可信的入口/传播能力、可核实的域名状态，以及可解释的关闭和回收过程。

本轮只核对源码和历史设计，未执行创建/关闭泳道、域名修改、路由变更、请求探测或集群验收；页面布局为设计建议。其他 agent 正在修改交付和实例模块，接手时复核 dirty tree 与当前代码，不覆盖其工作。

## 3. 核心概念

| 概念 | 用户理解 | 身份/展示原则 |
|---|---|---|
| 环境 | 在哪里运行、使用什么部署与访问策略 | 以真实 envId 为作用域，实际集群/namespace 单独展示；未核实就不承诺物理隔离 |
| 基线 | 本环境默认复用的服务版本 | `default` 为受保护的系统逻辑范围，可虚拟展示，不允许普通泳道创建/关闭 |
| 联调泳道 | 一组服务版本的组合，未覆盖项按规则复用本环境基线 | 属租户×环境，可跨多个产品联调；不等于单个产品的私有资源 |
| 分支/PR/批次 | 变更来源 | 与泳道为关联关系，允许不同分支进入同一共享泳道，不以字符串相等代替关系 |
| 服务预览地址 | 直达某个部署版本的入口 | 表达“入口落在哪个 workload”，不保证后续整条调用链 |
| 泳道联调入口 | 带可信上下文进入完整联调链路 | 只有入口绑定、上下文传播与范围校验具备时才启用该名称 |
| 内部地址 | 集群内服务发现或诊断地址 | 标明可达范围与端口，默认复制，不当作普通浏览器入口 |

泳道提供版本选择与运行组合，不能等同于数据库、缓存、消息队列或网络的完整隔离。详情展示“数据与配置隔离”说明：继承了什么、覆盖了什么、哪些资源共享、哪些未验证；不能把共享数据服务默认为每条泳道独立。

## 4. 身份、命名与兼容

- `Lane.id` 作为稳定引用，`name/key` 保持不可变的机器标识，新增可选 `displayName` 供中文业务名称；页面主要显示“支付改版”，辅助显示 `pay-v2`。
- 环境与机器 key 同时参与身份；“测试/pay-v2”和“预发布/pay-v2”是不同泳道。
- 来源保存为明确的 branch/PR/change/batch/run 引用；原分支 `feature/payment-v2` 不强迫用户手改为 DNS 名。
- 域名、K8s 名称由服务端统一生成短 slug+作用域哈希，校验冲突与长度；不简单截断长分支，不让 `a/b` 与 `a-b` 静默合并。
- 当前 `Workload.laneId` 实际存名字，与 Lane.id 不同；增量引入 `laneRef`，保留旧字段兼容，禁止前端自行混用。映射由租户+环境+旧 key 唯一解析；歧义保留待修复，不能任取一条。
- 已关闭泳道不自动因同名部署而复活；重新创建需要新稳定身份与入口绑定，旧分享地址不能静默指向新一轮验证。
- 基线、普通预览、共享联调、发布验证分开显示用途；standard/permanent 是保留策略，不是健康状态。发布验证应绑定具体 release/run，普通关闭入口指向该发布的终止流程。

本次不要求全仓迁 namespace/更换 mesh；先打通作用域和映射，按真实落点展示。

## 5. 路由选择与可信证据

### 5.1 默认行为

| 目标服务在所选泳道中的情况 | 处理 | 页面文案 |
|---|---|---|
| 已部署且 Ready 可用 | 选择该泳道实例 | 本泳道版本，显示实际 digest/实例 |
| 明确没有部署覆盖，且本环境基线可用 | 允许回退本环境基线 | 复用基线：显示来源环境与基线版本 |
| 声明了覆盖但 Pending/不健康/缩至 0 | 默认明确失败 | 本泳道版本不可用；不把失败藏进基线成功 |
| 读取控制面/数据面失败 | 返回未知/不可用 | 无法确认选路，不显示“已回退” |
| 泳道不存在、关闭或无权访问 | 拒绝 | 泳道不可用，不自动走默认入口 |
| 没有本环境基线 | 明确缺依赖 | 缺少可用基线，不跨环境借用 |

如业务确需“故障时也回基线”，将其作为显式可审计的策略，显示未验证覆盖风险，不能默认开启。生产稳定服务与测试联调不可互相回退。

上下文同时需要“是否显式指定”与值：请求明确选择 default 时必须覆盖容器的 SelfLane，不因空字符串归一重新回到 feature。经基线服务后仍保持原 requested lane，后续服务可以再次命中 feature。

### 5.2 部署态与请求态分开

泳道矩阵显示已知版本组合；路由预览只显示当前配置下的预计选择；TraceID 才展示一次真实请求的实际路径。不能用静态矩阵或动画证明命中。

示例（仅示意）：

```text
请求泳道：支付改版 pay-v2
入口 Web：基线 → 订单 API：pay-v2 → 库存 API：基线 → 支付 API：pay-v2
```

每跳证据至少有 requestedLaneRef/key、selectedLane、serviceRef、envId、workload/instance、version/digest、routeReason、routeConfigVersion、timestamp、traceId。现有 `paas.lane` 可能只表示请求上下文，不能直接把它当成最终命中的部署版本。未采集字段显示未知。

SDK/入口必须保持上下文且校验本环境；不经 SDK/代理的裸 DNS 直连单独标“传播能力未确认”。异步 MQ、定时任务、非 HTTP 协议不因 HTTP 联调成功而自动标已覆盖。

## 6. 泳道在页面中的展示

### 6.1 入口归属

- 产品“服务运行”增加局部运行范围：基线 / 选择泳道，按当前浏览环境分组；不新增与顶栏环境冲突的第二套全局环境选择器。
- 环境详情保留跨产品泳道管理与汇总矩阵；产品内显示所选泳道涉及本产品的服务版本。
- `/lanes/:id` 作为完整泳道工作区；旧链接保留，未实体化历史泳道使用只读兼容查询，查看不触发 POST。
- 全部环境时候选项按环境分组，标签显示环境+泳道；选择固定到具体 laneRef。详情始终展示实际环境，顶栏浏览范围变化不静默换目标。

### 6.4 矩阵单元格规则

同格同时表达部署来源、版本与观测状态：本泳道已部署 / 已确认复用基线 / 预计复用待验证 / 本泳道不可用 / 未接入 / 读取失败。不能因没有 workload 就一律画“↩ 基线”；不能用聚合副本数量推导所有服务都可用。

泳道实体列表与 workloads 取并集，空泳道、遗留未实体化项分别标识。可过滤临时/常驻/发布验证，关闭项默认收起并保留历史。颜色由用途与健康分开，文字和图标同时表达，支持亮暗主题与键盘。

## 7. 域名与地址的友好展示

### 7.1 按访问意图分类

| 名称 | 用户行为 | 说明 |
|---|---|---|
| 业务入口 | 打开 / 复制完整 URL | 本环境基线的正式或测试入口 |
| 泳道联调入口 | 打开 / 复制 / 查看链路验证 | 经可信 Host 绑定染色，后续已支持传播；未具备时标待接入 |
| 服务直达预览 | 打开 / 复制 | 指向某个具体工作负载，用于单服务验证 |
| 集群内部地址 | 复制地址/示例命令 | `.svc.cluster.local`、协议和端口，标“仅集群内” |

默认显示一个主要入口，其余“其他地址 n”。不把所有 host 作为无类型链接堆到服务表。复制保留真实协议、端口、path；多个 host 字符串需要正确拆分，不能整体拼成 URL。自定义业务域名优先保留，不因新命名规则自动改名。

地址卡示意：

```text
泳道联调入口                         测试 · 支付改版
https://shop-pay2-r8k4.preview.example.com/
目标：Web（基线） · 请求泳道 pay-v2
路由已下发 · DNS 待验证 · HTTPS 已配置 · 链路未验证
[打开] [复制] [查看访问详情]

订单 API · 服务直达预览
https://orders-pay2-p4t9.preview.example.com/api/
目标：订单 API / 测试 / pay-v2 / workload-…
验证范围：单服务入口；后续上下文传播待确认
```

示例域名不代表当前环境已配置 HTTPS 或联调网关。未提供准确 URL 时不由前端猜协议；HTTPS 由证书和入口能力确认，当前仅声明 HTTP 时如实显示。

### 7.2 平台自动域名

建议使用“可读短名+稳定作用域短标识”的单层主机标签，例如 `shop-pay2-r8k4.preview.example.com`。短标识由 tenant/env/app/入口服务/lane 身份生成，服务端检查唯一性，保留哈希长度预算；不直接暴露租户内部 ID，不使用单纯分支截断。

单层结构方便统一 wildcard DNS/证书配置；K8s Ingress 的 `*.preview.example.com` 主机匹配只覆盖一个标签，不能假设它同时匹配 `api.pay2.preview.example.com`。[官方 Ingress 文档](https://kubernetes.io/docs/concepts/services-networking/ingress/)

访问地址不等于工作负载名字，内部 K8s 名可以保留兼容；地址一旦分享，生命周期与绑定版本明确，关闭后返回可理解的已关闭结果，不进入默认后端或其它泳道。自定义域名的 DNS、TLS、path 与租户授权独立校验。

### 7.3 地址状态与所有权

状态分开记录：配置保存、控制器下发、DNS、TLS、后端就绪、请求命中验证。每项带时间和探测位置；core Pod 可达不能推导用户浏览器可达，集群内 smoke 通过也不能推导外部 DNS 已就绪。

现有 Workload.domain 与治理 Route 都能生成 Ingress；建立统一 AccessEndpoint 读模型，保留 source/ref 和实际 target，统一预览与冲突检测，明确每个 host/path/入口范围的唯一配置归属。产品页不再按名字串接域名。相同 host/path 的跨来源冲突应阻止写入，不把控制器随机选择当可用方案；跨租户占用错误不得泄漏他人资源详情。

保留现有写入口但统一目标与冲突规则。用户撤下域名后继续观察实际路由是否退场；有残留显示未完成，不只显示“已保存”。

## 8. 打开域名后为何能进入泳道

普通浏览器链接不能自动携带自定义 Header。仅复制域名或给 URL 加 `?lane=` 不会让现有 Ingress/SDK 自动接入全链路。

联调入口的目标能力：服务端将一个 Host/path 与租户、环境、laneRef、入口服务绑定，经过权限检查，向该入口注入可信泳道上下文；入口若复用基线服务，也必须保留 requested lane。服务间通过 SDK/受支持代理继续传播，按同环境解析对应版本。前端若把 API 地址写死到正式域名，也不能声称已完成泳道联调。

该能力须由现有入口控制器/治理适配器核实并实现，不要求引入 Istio 或新独立网关微服务。当前普通 Ingress 若只支持直达服务，第一批就明确显示“服务直达预览”；满足绑定、传播与实测证据后才升级为“泳道联调入口”。

外部传入的 lane Header 不作为权限凭证，入口映射和服务端授权决定允许的上下文；未经验证的 Header 不能覆盖受信 Host 的租户/环境绑定。复制链接不会自动授予访问权；需要受控分享时使用可撤销、有限期机制，避免把平台 API Key/会话凭证放 URL，也不把控制台 cookie 透传业务服务。

首版只承诺明确覆盖的 HTTP 链路。不要为“看起来一键”隐藏未接入 SDK、跨域 API、共享数据或异步任务的边界。

## 9. 生命周期与关闭体验

- 创建只要求名称、实际环境、临时/常驻；分支/变更可选关联。验证完成后显示是否已有入口；没有服务时引导部署，不显示假地址。
- 临时泳道显示真实 retention policy、最后活动依据、预计 eligibleAt 和后台扫描时间；当前 TTL 主要依据部署/流水线活动，不应写成“72 小时没人访问自动删除”。
- 提供显式延长保留/改为常驻能力时需后端支持和权限；浏览详情不刷新 TTL，常驻泳道显示治理责任与定期清理提醒，不因有访问量就无限保留。
- 普通联调默认在测试类环境；生产发布验证从 release/run 创建并由其流程管理。服务端明确拒绝普通生产联调或按独立策略授权，前端与后端保持一致。
- 关闭前预览影响：涉及产品/服务/实例/入口、运行与配置覆盖、共享资源保留项。跨产品泳道应显式显示影响范围，检查每个目标的权限或平台管理权限；不能只按泳道名字确认。
- 关闭期间禁止新部署、更新入口、创建依赖；用稳定 laneRef/实际运行目标检查进行中部署、终端、验证任务，不能用 branch==name 代替关联。
- 生命周期与资源回收状态分开：关闭请求已受理 → 正在回收 → 已关闭且已清理，或部分失败/待重试。记录每项实际结果、错误和审计，后台可恢复；HTTP 成功不等于资源已全部退场。
- 不删除复用的基线和共享 DB/缓存；明确是否删除泳道配置覆盖与临时入口。基线 default 在 UI、handler、repo/回收器均保护。permanent 的部分失败必须能重试，不能指望跳过常驻项的普通 TTL 扫描自动完成。

## 10. 增量数据与接口建议

这些是待开发契约，不是现有可用能力。复用 lane/workload/governance/pipeline 领域，避免新建一套独立域名系统。

### 10.1 读模型

- `LaneSummary/Detail`：稳定引用、displayName、真实环境、用途/来源、保留策略、capabilities、各子资源读取状态、观测时间；关闭结果/剩余资源单独字段。
- `EffectiveServiceRow`：serviceRef、selectedEnv、laneRef、declaredOverride、expectedSelection、observedSelection（若有）、baselineRef、workloadRef、版本/就绪/原因、SDK/传播覆盖状态。
- `AccessEndpoint`：id/kind/sourceRef/targetRef、完整 URL 或内部地址、协议/host/port/path、上下文绑定能力、访问范围、声明与观测状态、各检查时间/位置。
- `RouteResolution`：requested/selected lane、环境与服务、实例、reason、配置版本、时间；预览与真实请求证据分字段。
- `CloseOperation`：影响快照、expectedRevision、阶段、每个回收项状态、剩余资源、失败原因、可重试能力和审计。

### 10.2 API

| 路径/能力 | 行为 |
|---|---|
| 扩展 `GET /api/lanes`、`GET /api/lanes/{id}` | 加读模型，列表包括空泳道；子查询失败独立表达，不能变零 |
| 增加遗留泳道只读解析 | envId+laneKey 定位，只读不创建；跨租户/歧义返回明确结果 |
| 增加 `GET /api/lanes/{id}/access` | 返回带精确目标和来源的地址；不根据名字猜测 |
| 增加 `POST /api/lanes/{id}/routing-preview` | 只读解析预期选路，不执行用户任意 URL 请求；与实际 Trace 证据区别 |
| 增加关闭影响预览与关闭操作查询 | 版本化影响快照、受理与结果；沿用 DELETE 可兼容扩展，新增客户端必须读取真实结果 |
| 增加路由绑定/验证能力 | 仅支持的入口适配器开放；HTTP 入口、DNS/TLS 和真实链路验证分开，受权限/频率限制 |

data-plane SDK 保持旧协议兼容，增量返回解析范围与原因；逐步引入带环境/服务稳定引用的解析路径，旧调用基于权威映射并拒绝歧义。并发关闭/部署、幂等、归属校验与冲突保护在服务端完成。OpenAPI route registry 为契约真源，memory/PG 同义，追加 migration。

## 11. 验收

1. 基线不能被建成可关闭的普通泳道；任意回收路径均拒绝删除 default。
2. A(基线)→B(feature)→C(基线)→D(feature) 保持 requested lane，实际每跳有版本与实例证据。
3. feature 未覆盖可回基线；已部署不健康、缩 0、查询出错不静默回退；不同环境不串路由。
4. 同租户两环境同名泳道、两个产品同名服务、`a/b` 与 `a-b`、长分支、跨租户同域名均不混目标。
5. viewer 查看遗留/空泳道不产生写请求；空/失败/未知状态正确。
6. 复制 URL 保留协议、端口和 path；内部地址不伪装外部入口；TLS/DNS/Ingress 各有真实状态。
7. 仅有直达域名时不显示全链路联调可用；SDK 缺失、显式 default、浏览器跨域、经过基线重入泳道均覆盖。
8. 查看关闭影响能识别跨产品范围；active run 与显式自定义 lane 关联正确；部分失败可重试，常驻与临时均可恢复清理。
9. 读页面不续期、不隐式创建；关闭旧泳道后旧域名不进入新泳道或默认后端。
10. 390/768/1024/1440px、亮暗主题、键盘、不同角色检查；本地/fake client/真实入口与链路验收分别报告。
