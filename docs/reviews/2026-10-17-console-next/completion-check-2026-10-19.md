## 优先补齐的具体项

### 1. 配置并发保护不足（P1）

证据：`frontend/console-user-v2/src/components/SharedConfigEditor.vue:331`；`internal/configcenter/memory/store.go:569`；`internal/configcenter/pg/store.go:791`。

当前传 expectedCount，只比较覆盖条目数。其他操作者把已有 key 的值从 A 改成 B，数量不变，旧预览写 C 仍能通过；前端还是提交时重新读取 count，而不是锁定预览版本。读取失败时传 -1，会跳过该检查。PG 代码注释称锁现有行，当前实际该段只有 `SELECT count(*)`，没有所述行锁。

这不否认批次事务能保证单次操作原子性，但不能满足设计要求的版本漂移保护。应使用预览时 revision/hash＋原子比较更新，读取失败不能降级为无并发保护；补同条目数修改、空集合并发和重复提交场景。

### 2. Playground 能力限制未贯穿所有入口（P1）

证据：`frontend/console-user-v2/src/views/Playground.vue:60`、`:77`、`:167`；目录的 `Models.vue:44` 已有能力分流。

Playground 下拉仍加入所有目录模型，模式仅区分 embedding 与其他；非 chat、非 embedding 模型通过下拉或直达 query 仍进入对话发送逻辑。应在控件与发送前同时验证受支持端点，不能只在模型目录禁用入口。

同时当前 SSE reader 在流结束时直接退出，未建完整的成功/取消/异常完成状态；错误帧与解析失败仍需专项验证。MD-02 的 HTTP 错误隔离已改好，不应继续列为原样未修。

### 3. Agent 依赖摘要不等于运行能力就绪（P1）

证据：`frontend/console-user-v2/src/views/ai/Agents.vue:93`、`:534`；`internal/ai/agent/runtime.go:96`、`:122`、`:141`。

当前摘要主要检查引用存在/启用；工具选择器仍仅按 enabled 禁用，HTTP/builtin 可被选入，而运行端仍仅支持 MCP。知识库检索失败、Skill 缺失仍静默跳过，模板仍直接使用文本。前端元数据“就绪”不能表示远程依赖和完整运行能力已通过验证。

补真实可调用约束、运行 warnings/实际采用资产、必需依赖规则；Prompt 输入与渲染按同一后端契约实现。刷新引用失败后不应继续把旧成功读取标志当作新鲜证据。

### 4. API Key 明文清除未落地（P1）

证据：`frontend/console-user-v2/src/views/ApiKeys.vue:103`。

关闭弹窗只设置 showCreated=false，createdKey 未显式清空，也未看到关闭回调清除。按设计在弹窗关闭、路由离开和退出时清理明文状态；此项是前端生命周期改善，不等同于已确认服务端明文泄漏。

### 5. “有运维记录”与真实备份恢复仍有边界（P1）

证据：`internal/backup/handler.go:168` 与 `deterministicSize`；`DataServiceOperations.vue` 已明确记录模式。

后端仍直接生成 completed 和模拟大小，没有真实备份作业、可恢复产物与恢复校验。应保留诚实边界，再选择受支持引擎完成隔离环境的备份→恢复新实例→读回验证；不能用已有页面和记录列表验收灾备能力。

### 6. 契约与访问/用量仍需收尾（P2，部分基础错误态为 P1）

新批次与采集质量端点已登记 route registry，但当前 `src/api/types.gen.ts` 未发现对应路径，不能认定生成类型同步完成。工作流与配置 PG 迁移有源码，但本次没有运行数据库迁移或集成验证。

`Billing.vue:103` 的读取仍只处理 resp.ok，未提供明确非 2xx 错误态；主界面仍显示“生成本期账单”等，估算/当前快照口径与真实时段用量尚未形成一致表达。Key scope/有效期、Secret 引用轮换、真实结算也未见本轮完整实现。
