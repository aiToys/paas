# 用户端首个 Agent：连续对话改造记录

日期：2026-10-28

后续部署状态：已完成 K8s Helm revision 405 升级及无模型调用验收；新增真实模型诊断验收待单独数据传输确认。具体见 [部署记录](deployment.md)。下文保留实施阶段的本地验证范围。

本轮在现有未提交实现上完成本地改造，保留其他工作区修改；未提交、推送或部署到集群。

## 最终用户体验

- 顶栏 AI 助手打开最近会话；同一面板提供 Agent 选择、历史、新对话与固定目标。
- 每轮用户问题和助手回答按时间连续显示，不再只展示当前 activeRun。
- 工具进度和诊断报告属于各自回答，按需展开；输入框始终位于底部。
- 关闭重开、刷新和历史入口均从服务端恢复消息。未发送的新对话草稿在关闭重开时保留；切换身份后清理内存与轮询。
- 「讨论已有证据」读取历史报告和最近问答，明确历史时间；「检查最新状态」重新取证。
- 原本误用 run ID 的会话链接会解析到真实 session ID。

## 可复用基础

- `Message` 是用户端统一协议，稳定 ID、角色、正文、状态和 resultKind。
- question/reply/artifact 与运行终态存储在同一持久化轮次，消息通过 API 原子投影；旧诊断记录无需复制为第二份真源即可恢复。
- 官方目录和 `Executor` 分派与诊断页面分离。新 Agent 可以返回自然语言及其他版本化 artifact。
- `RunInput.Invoke` 是已接入授权、预算准入、用量和工具进度的模型调用入口；不能另建绕过配额的客户端。
- OpenAPI 补全消息、会话、任务、事件响应与幂等头；公共前端类型生成到 `assistant.gen.ts`。修正 reflector 将 RawMessage 误认作字节数组的问题。
- 接入说明见 `docs/development/user-agent-integration.md`。

## 修复的诊断与执行问题

1. 规范化 typed nil 数据源，后台 panic 收敛为单任务失败。
2. 模型实际接收有界脱敏日志片段，取证信封和账本使用同一证据内容。
3. 空序列不当作零指标；error/missing 证据不成为充分根因依据；全部假设无效时重写顶层结论。
4. Pod/owner 链与 UID 校验、容器校验、日志读取后复核；Loki 按授权实例精确查询，固定绝对窗口并过滤返回结果。
5. 取消中断运行 ctx，已取消排队任务不进入模型；有界工具调用与每轮预算准入。
6. memory 锁和 PG 事务准入保证并发限额；幂等索引及重放，拒绝空身份放宽 owner。
7. Worker 心跳、失联回收、lease owner fencing；报告、回答与终态事件一次保存。
8. 用户问题和工具文本脱敏；发起、停止和终态写入审计。
9. 逐轮 token 配额预留、结算和周期用量记录，真实 usage 和估算口径分开。
10. 默认对话 30 天、原始证据片段 7 天；片段过期保留消息及证据元数据，内存模式明确提示重启丢失。

数据库新增迁移为 `0061_assistant_conversation`，保留既有 `0060` 文件及其 RLS 和租户 policy；对话升级不关闭行级安全。助手访问继续强制显式 tenant/user 校验，跨租户队列仅供后台使用。当前开发集群复用已有受信任 Core 数据库角色；该角色原本为超级用户，RLS 不约束其查询，不应据此声称已完成数据库最小权限隔离。改用无 BYPASSRLS 的运行角色前，仍需完成请求级租户参数与独立 Worker 连接权限设计。
