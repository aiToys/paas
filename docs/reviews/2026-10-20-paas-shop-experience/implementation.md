# PaasShop 泳道与能力体验优化

日期：2026-10-20。范围：示例应用，不修改 Platform Core 或其他已有工作区改动。本地实现与验证记录；后续已完成集群 Git 提交及测试发布，见 [deployment.md](./deployment.md)。

## 完成内容

- BFF 新增 `GET /api/platform/lanes`：部署环境固定作用域，服务端读取平台环境和活跃泳道；生产不提供联调候选；凭证与集群内地址不返回浏览器；拒绝写方法与平台重定向。
- 前端改为选择泳道，按环境保存稳定 ID，请求发送平台泳道名称；支持基线、刷新、列表失败、生产禁用、域名固定、历史泳道失效提示。切换时重置订单、客服、详情等视图状态，避免继续操作旧泳道。
- 数据面发现保留错误与空实例语义：启用发现后失败或空结果停止转发，平台负责未覆盖时的回退；未启用发现只允许静态基线。成功发现结果缓存 10 秒，发现失败不缓存。
- 商品与推荐分别显示请求泳道、平台返回的泳道、回退原因及下游实例。Trace 存在且已配置外部控制台时提供精确查询链接。它不替代完整调用链及版本核验。
- 新增可展开的六条体验路径：泳道、配置、AI 审批、事件与任务、交付、数据服务。明确 HTTP 泳道与环境级消息/统计的边界，不将配置状态当成验收结论。
- setup 脚本补充环境类型、真实产品 ID、浏览器控制台地址配置；更新演示指南。本地 Vite 增加 BFF 代理，未新增依赖。

## 验证边界与下一步

本节保留实现阶段的部署要求；实际测试发布与依赖恢复结果见 [deployment.md](./deployment.md)。真实模型供应商调用未验收。部署需要更新 Shop BFF 与 frontend 两个镜像，并通过已有配置管理补齐 PAAS_SHOP_APP_ID、PAAS_CONSOLE_URL、PAAS_ENV_TYPE；不得直接运行整个 setup 脚本来替代增量部署。

现有平台 `/dp/instances` 会把部分底层读取错误转换为空列表；示例对此停止转发，不将其解释为已确认的实例健康故障。列表为租户内当前环境的泳道，是否覆盖 Shop 由请求结果核实。流水线自动工作负载名与发现 Service 名是否一致仍需真实集群对照，不能仅凭本地模拟通过宣称闭环。

备份恢复、离线交付、多租户权限和配额计费等仍是平台独立验证场景；退款 MCP 仍连接测试订单，消息与统计当前按环境聚合。

当前运行连接没有被本轮重启；需重启 Codex 后观察实际传输与超时是否消失，不能据此宣称网络根因已修复。
